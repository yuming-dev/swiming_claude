1  文档目的

本文描述游泳计时系统主服务器（SwimmingScoreboard.exe）与硬件计时控制器之间的 串口 / UDP / TCP 帧级通讯协议。本版（v2026.05）是 v2026-06 主协议（2026-05-10）的完整继任版， 合并了 2026-05-13 后陆续推出的所有增量改动。

2  物理层与帧结构

2.1  物理层

项参数
链路串口（推荐）/ UDP / TCP 任选其一
串口参数9600 baud, 8 data bits, no parity, 1 stop bit（9600 N81）
主服务器界面可改 9600 / 19200 / 38400 / 57600 / 115200，落盘到 timing_connection.json。
字节序按字节顺序发送；所有参数值为 8 位无符号整数；多字节数值字段（如 0x4B 电压）单独说明大小端
帧定界起始字节 0xF1，结束字节 0xF4
帧长固定 12 字节

2.2  帧结构

位置字段值 / 含义说明
D0SOH0xF1起始标识（固定）
D1'S'0x53协议识别字符（固定）

2.3  时间字段编码

以 "1 小时 23 分 45.678 秒" 为例（01:23:45.67 加 8 ms）：

字段D5 分D6 秒D7 1/100 秒D8 (小时<<4)|ms1
值0x17 (23)0x2D (45)0x43 (67)0x18 = (1<<4)|8

解码公式：time = hour·3600 + min·60 + sec + cs/100 + ms1/1000

4  时间帧（运动员事件类）详细布局

4.1  0x16 / 0x17 / 0x18 / 0x19 触板与盲表

字段含义
D20x16 = 触板 / 0x17 = 盲表 1 / 0x18 = 盲表 2 / 0x19 = 盲表 3
D3子码（保留 0）
D4泳道号：0–9 = 终点端泳道；10–19 = 另一端泳道（实际泳道 = D4 − 10）
D5–D8时间编码：分 / 秒 / 1/100 秒 / (小时<<4)|ms1（见 2.3）
D9–D10保留 0

4.2  0x1A StartingBlock — D10 抢跳符号位 2026-05-13

出发台反应时帧。字段同 4.1，新增 D10 字节：

D10含义
0x00正常出发（运动员晚于发令枪）
非 0抢跳 / 犯规（运动员早于发令枪）。PC 端应把 TimeInSeconds 取负显示（如 −0.020 s）

PC 端实现：if (cmd == 0x1A && rawD10 != 0) { isFalseStart = true; timeInSeconds = -timeInSeconds; }

4.3  0x1C / 0x1D / 0x20 / 0x21 控制帧

命令方向语义
0x1C双向StartCommand：发令枪 / 开始计时（无参数）
0x1DPC→HWTestCommand：设备测试模式（无参数）。硬件接收后进入测试模式：所有 TP / SB / MB 触发均允许并立即上报；PC 端 _testMode = true，UI 显示"设备测试"红色徽章
0x20双向TimerReset：计时清零（无参数）。注意：硬件 0x20 会清掉内部缺道位图，主服务器收到后必须补发 0x7F + 0x43
0x21双向TimerReady：准备就绪（无参数）。通常在 0x43 Set_MatchEvent 之后下发

4.4  0x7F RunningTime（滚动时间）

硬件每约 100 ms 主动上报一帧，作为主服务器的权威时钟源。字段同 4.1（D4 = 0），主服务器更新内部 _runningTime 并立即广播 RUNNING_TIME_UPDATE 给所有客户端。

5.1  0x39 Set_DateTime PC→HW 2026-05-13

连接建立后 PC 主动一次性下发，让硬件 RTC 对齐计算机时钟。建议每 30 分钟周期重发（PC 端 _clockSyncTimer）。

字段含义
D3年低字节 year & 0xFF
D4年高字节 (year >> 8) & 0xFF
D5月 (1–12)
D6日 (1–31)
D7时 (0–23)
D8分 (0–59)
D9秒 (0–59)
D100

5.2  0x3A Set_PoolSingleOrDoubleTP 双向 2026-05-132026-05-16 双向

泳池触板"单边 / 两端安装"配置。硬件需持久化到 SD 卡（或 BKPSRAM）。

字段含义
D30 = 两端安装  |  1 = 单边安装
D4–D10保留 0

触发：

  • PC→HW：用户切换"单边 / 两端"，PC 下发；连接建立时同步当前配置
  • HW→PC：硬件 net_test 子界面用户切换 PoolSingleOrDoubleTPbtn 后返回主控时上报
防回环：硬件上报时 PC 不回发 0x3A；PC 下发时硬件处理完不回报。

5.3  0x41 Set_ArmDelay_Time（核心参数包）PC→HW

主服务器"参数设置"对话框点击确定后，所有触板 / 盲表 / 出发台的延迟、显示时长、发令端、道次方向都打包在这一帧里：

字段含义单位说明
D3ArmDelayNormalTime秒触板正常关闭时间 = LaneCloseTime（默认 20）
D4ArmDelayAfterStartTime秒抢跳后触板关闭时间 = LaneCloseTime
D5BlindReplaceDelay 05.13 语义0.1 秒盲表代替成绩延迟时间（无 TP 时盲表数据等待此时长后落地）。50 = 5.0 秒；硬件内部 MBdelay_Time = d5 * 10
D6Result_Display_Time秒分段成绩显示时长 = SplitDisplayTime（默认 5）
D7StartboxEdgeBit0/1出发信号边沿：0 = 下降沿，1 = 上升沿。默认 0
D8方向 / 50m / 终点端 三合一 05.26 纠正位
bit 4bit 1bit 0
LaneDirectBit (1=逆序 9→0 / 0=正序 0→9) StartPlace50MBit (1=50 米发令端不同于终点) FinalPlaceBit (0=终点左 / 1=终点右)
即 D8 = LaneDirectBit * 16 + StartPlace50MBit * 2 + FinalPlaceBit
2026-05-26 协议纠正：bit 0 在硬件 swimplay.c 中本来就一直是 FinalPlace（终点端）， PC 端之前误当作 StartPlace（起点端）发送。100m+ 比赛 sp50m=0 时 StartPosition == FinishPosition，两个值编码相同所以没暴露问题； 50m 单程 sp50m=1 时 Start ≠ Finish，编码不同导致硬件出发台开错端、 方向错、后续触板/盲表错位。PC 端已修正（commit b45274e）发送 FinishPosition。 硬件端不需要任何改动。
D9TPDelayTime秒触板关闭延迟 = ResultConfirmCloseDelay（默认 3）
D10SBDelayTime秒出发台关闭延迟 = StartBlockCloseDelay（默认 3）

5.8  0x46 Set_TPSBMB_State PC→HW 2026-05-13 语义

"设备状态管理"对话框确定后下发；包含触板 + 出发台 + 盲表 1 三大类、左右两端共 20 个泳道、共 60 个启用位。每一类有 20 位：bit 0..9 = 左端 0..9 道，bit 10..19 = 右端 0..9 道。 位 = 1 表示该位置启用；位 = 0 表示损坏 OR 未安装（硬件无须区分原因，停止期待该端信号即可）。

字段含义编码
D3State[0]TP_Value bit 0..7
D4State[1]TP_Value bit 8..15
D5State[2]TP_Value bit 16..19（仅低 4 位有效）
D6State[3]SB_Value bit 0..7
D7State[4]SB_Value bit 8..15
D8State[5]MB1_Value bit 0..7
D9State[6]MB1_Value bit 8..15
D10State[7]高 4 位 = SB_Value bit 16..19；低 4 位 = MB1_Value bit 16..19

盲表 2 / 3 扩展（0x49 / 0x4A）：同 0x46 MB 段格式，D3..D5 为 20 位，D6..D10 保留 0。当前固件未识别会忽略，主服务器持续广播帧已就位，待固件升级即生效。

5.9  0x47 Set_LaneOpenClose 双向 2026-05-142026-05-16 双向

泳道整体启用 / 禁用（关闭的道相当于空泳道，硬件不接受其任何信号）。

字段含义
D3泳道号：0xFF = 全部道；0x00 – 0x09 = 指定单道
D41 = 打开（纳入比赛）  |  0 = 关闭（完全屏蔽）
D5–D10保留 0
与 0x60 / 0x4C 三命令的语义区分：
  • 0x47 道次开/关 — 全部或单道 TP/SB/MB 整体启用/禁用（不动道次按钮显示）
  • 0x60 单道屏蔽 — 仅单道整体启用/屏蔽（同时切换道次按钮显示状态）
  • 0x4C 设备全开 — 设备状态机覆盖（接受所有信号 vs 按状态过滤）
0x47 = 关闭 优先级最高；被关闭的道无视 0x4C = 全开 也不上报。

双向触发：PC→HW 由 PC 端"全部打开 / 全部关闭 / 道次打开 / 道次关闭"4 按钮触发；HW→PC 由硬件 net_test "封闭/不封闭TP"切换后退出时主动上报（PC 同步 LeftTouchpad / RightTouchpad / LeftBlindWatch1-3 / RightBlindWatch1-3 状态）。

5.10  0x4C Set_ForceAllOpen PC→HW 2026-05-13

"设备全开"模式：硬件忽略 TP/SB/MB 内部状态机，任意信号都按"Open"上报。

字段含义
D30xFF = 全部道  |  0x00 – 0x09 = 指定单道
D41 = 进入"全开"  |  0 = 恢复正常状态机
D5–D10保留 0
建议：进入"全开"模式时，硬件点亮 LED 或屏幕加显标识，让操作员能直观看到"特殊模式"在生效。状态 3 (坏) / 4 (未安装) 不会被 0x4C 覆盖。

5.11  0x60 Set_LaneEnableDisable PC→HW 2026-05-17

操作员手动屏蔽 / 启用某单道（仅作用单道，不支持 0xFF 全部道）。

字段含义
D3泳道号 0x00 – 0x09（必须单道）
D41 = 启用  |  0 = 屏蔽（任何 TP/SB/MB 信号都不上报）
D5–D10保留 0

5.12  0x61 Set_LapRemaining PC→HW 2026-05-17

PC 端"剩余圈数 +1 / −1"按钮触发，把改后圈数下发硬件。硬件 laps[D3][D4] = D5，并调 LLaps_diaplay / RLaps_diaplay 重画对应道次的圈数显示。

字段含义
D3泳道号 0x00 – 0x09
D4端：0 = 左侧  |  1 = 右侧
D5剩余圈数 0 – 255
D6–D10保留 0

5.13  0x62 Set_LaneOrder 双向 2026-05-17

道次顺序（影响 PC 与硬件双方的道次显示编号）：

字段含义
D30 = 正向 (0→9)  |  1 = 反向 (9→0)
D4–D10保留 0

双向：PC→HW 由用户切换 PC 端参数；HW→PC 由硬件 net_test 切换后返回主控上报（PC 端不回发，防回环）。

5.14  0x63 Set_FinishPosition 双向 2026-05-17

字段含义
D30 = 终点左端  |  1 = 终点右端
D4–D10保留 0
PC 端收到 0x63（HW→PC）后必须同步触发：
  1. _laneCloseSettings.FinishPosition / StartPosition 更新
  2. ApplyTouchpadInstallModeToLanes() 刷新各道 NotInstalled 标记（单端模式下"非终点端"由 FinishPosition 决定）
  3. Broadcast() 推给所有客户端

5.15  0x65 Set_RefreshDisplay PC→HW 2026-05-18

PC 端"参数设置"对话框 OK 后下发，让硬件按新参数主动重画主控界面（不丢失"缺道 / 剩余圈数"等比赛状态）。

字段含义
D3–D10全部保留 0
硬件实现要点：必须先保存 CloseLaneState[10]、laps[10][2]、TP/SB/MB 状态 → 调 SwimControl_init() 重画 → 从保存值恢复重画各道状态。否则用户在比赛进行中改参数会丢失缺道 / 剩余圈数。

6  硬件主动上报帧

6.1  0x4B BatteryVoltage HW→PC 2026-05-13

电池电压周期上报（建议每 5–10 秒，或电压跳变超过阈值时）。

字段含义
D3电压 mV 高字节（BIG-ENDIAN）
D4电压 mV 低字节
D5–D100

PC 端解析：mV = (D3 << 8) | D4，V = mV / 1000.0。
硬件电池：7.4 V 标称（2 节锂电串联包）。两节合计 6.0V 耗尽 / 7.0V 低 / 7.4V 标称 / 8.4V 满充。

显示色彩阈值电压区间含义
🔴 红色< 7.00 V严重低电，立即更换/充电（接近耗尽截止 6.0V）
🟡 琥珀色7.00 V – 7.40 V偏低，注意监视
🟢 绿色≥ 7.40 V健康

6.2  0x64 Set_TimingsBundle（5 项时间数据反向同步）HW→PC 2026-05-17

硬件 net_test 子界面用户编辑完 5 项时间编辑框后退出，把当前值打包上报给 PC：

字段含义单位
D3泳道封闭时间 LaneCloseTime秒
D4触板延迟关闭时间 ResultConfirmCloseDelay秒
D5出发台延迟关闭时间 StartBlockCloseDelay秒
D6盲表代替成绩延迟时间 BlindReplaceDelay秒

单位说明：BlindReplaceDelay 单位 2026-05-18 起统一为"整数秒"。硬件 0x41 D5 / 0x42 子码 0x09 接收时仍按 0.1 秒（旧）解析；新协议 0x64 D6 按整秒。PC 端发送旧 0x41 / 0x42 时按"整数秒值 × 10"塞入兼容旧硬件。

0x39 D3..D9 = year-lo/year-hi/月/日/时/分/秒            // 校 RTC

0x44 D3 = Lanes  D4 = PoolLen                          // 泳池

7.4  设备测试模式

  1. 本端弹确认框（远端通过 WebSocket DEVICE_TEST_TOGGLE 请求服务器，服务器切换）
  2. 主服务器 _testMode = true；清空 _rawTimingLog；所有非损坏 / 未安装设备置 Open
  3. 下发 0x1D Test_Command 给硬件 → 硬件进入测试模式：所有 TP/SB/MB 触发都允许并直接上报
  4. 硬件来事件 → 跳过比赛状态 / 空泳道过滤 → 写日志 "【测试】..."
  5. 三端状态徽章覆盖红色 "设备测试"
  6. 再点一次按钮退出

8.1  硬件 BKPSRAM 持久化 2026-05-20

STM32 H7 Backup SRAM (4KB @ 0x38800000, VBAT 备份) 持久化 SwimMatchState_t 结构 v2，含：

  • 参数（StartFinalPlace / SwimmingPool_Arrage / Pool50mOr25mbit / PoolSingleOrDoubleTPbit / Left_MB_Num / Right_MB_Num / Open_State / Close_Time / ...）
  • TP / SB / MB 状态
  • CloseLaneState / laps / RelayBit / RelayLaps
  • 当前计时 hour / minute / second / msecond + timer_bit / Ready_timer_bit
  • local_ip[4] + local_ip_valid（v2 新增，2026-05-20）

触发：硬件 net_test "修改本机IP" 弹窗 OK / 主循环每 10 秒自动 Save。开机：swim_play → lwip_comm_init → DHCP → Load_State_From_BkpSRAM() → 若 local_ip_valid == 1 → 覆盖 lwipdev.ip + netif_set_ipaddr 应用。

8.2  远程 EXE 转发子命令族 2026-05-19

RemoteTimingControl（远程计时控制 EXE）直接连硬件时，把硬件 → PC 的扩展命令（0x4B / 0x47 / 0x3A / 0x62 / 0x63 / 0x64）拆为具体 WebSocket TIMING_CMD 子命令转发给主服务器：

硬件帧WebSocket TIMING_CMD 子命令data 字段

8.3  硬件 net_test "修改本机IP" 弹窗 2026-05-20

不涉及网络协议字节，但影响硬件本地 UI：

  • 位置：参数设置界面，"网络协议选择"按钮的同列上方（x = tempx）
  • 交互：按下弹出 sysset_ip_set(...) 模态对话框（仿 sysset_date_set 模式，260×200 窗口）。4 段 IP + 段间点号 + 每段 ± 按钮 + OK / Cancel
  • OK 后：写入 lwipdev.ip + IP4_ADDR + netif_set_ipaddr 实时应用 + bkp_local_ip_valid = 1 + Save_State_To_BkpSRAM 持久化
