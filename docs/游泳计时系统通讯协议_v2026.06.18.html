一、协议总览

1.1 通信层次

层协议用途
消息总线WebSocket :3002主服务器 ↔ 所有客户端 (display / RDC / RTC / Editor / register / 等)
Web 文件服务HTTP :8080主服务器提供 display.html / control.html / race_control.html 等
硬件计时器TCP :5555 / UDP :5002 / 串口主控 (主服务器或 RTC) 与硬件 STM32 通信

1.2 WebSocket 消息格式

所有消息均为 UTF-8 JSON 文本帧, 至少包含 type 字段:

{
  "type": "REMOTE_CONTROL",
  "command": "SHOW_LIVE_RACE",
  ...其他字段
}

1.3 主服务器消息路由 (HandleMessage)

type处理
*_IDENTITY将 socket 注册到对应客户端集合 (_displaySockets / _editorSockets 等)
REMOTE_CONTROLHandleRemoteControl — 显示模式 / 媒体 / PPT 等
TIMING_CMDHandleTimingCommand — 计时控制 / 比赛流程 / 成绩发布
RTC_FORWARD 新透传 payload 给所有 _allSockets, 缓存到 _lastRtcSnapshot

SET_DISPLAY_STYLE / GET_DISPLAY_STYLE大屏样式设置 / 查询
LOCK_REQUEST / LOCK_RELEASE编辑锁请求 / 释放
GET_HEAT_SWIMMERS / SAVE_CHECKIN / REGISTER_SWIMMER...数据查询与变更

五、RTC 转发链 (RTC_FORWARD) v2026.06.18 新增

5.1 设计目的

RTC 模式下, RTC 直连硬件计时器, 但不开自己的 WebSocket Server (避免与主服务器端口冲突)。 RTC 通过已建立的 EditorSyncClient 连接, 把比赛状态包装成 RTC_FORWARD 发给主服务器, 主服务器解包 payload 后透传给所有 display.html / race_control.html 客户端。

5.2 消息格式

RTC → 主服务器:
{
  "type": "RTC_FORWARD",
  "payload": {
    "type": "SHOW_LIVE_RACE",     // 或 RUNNING_TIME_UPDATE / SHOW_HEAT_RESULT / DISPLAY_STYLE_PUSH...
    "data": { ... 实际数据 ... },
    "modeExplicit": true          // (可选, BroadcastDisplayMode 加此标记)
  }
}

主服务器 → 所有 _allSockets:
(直接发 payload 内容)
{
  "type": "SHOW_LIVE_RACE",
  "data": { ... },
  "modeExplicit": true
}

5.3 主服务器 RTC_FORWARD 处理

case "RTC_FORWARD":
  string json = payload.ToString(Formatting.None);
  string ptype = payload["type"].ToString();
  if (ptype == "SHOW_LIVE_RACE") _lastRtcSnapshot = json;  // 缓存最新快照
  // 后台 Task.Run + lock _broadcastSerialLock 保证顺序
  foreach (s in _allSockets.ToArray()) s.Send(json);

5.4 新连接 display 的初始化

主服务器在 OnOpen 时:

if (_lastRtcSnapshot != null) socket.Send(_lastRtcSnapshot);  // 立即喂完整快照
else BroadcastSingle(socket);                                    // 否则发主服务器自己的状态

5.5 RTC 端节流

RTC 端 Broadcast() 100ms 节流 (BroadcastImmediate via DispatcherTimer), 避免事件密集时 连续 GetStatusData() 拖慢 UI 线程。100ms 内多次调用合并为 1 次真正广播。

六、编排同步 (EDITOR_*)

6.1 整包推送

消息方向用途
EDITOR_PACKAGE主服务器 → Editor整包数据 (赛事/项目/运动员/赛程/纪录)
EDITOR_PULL_PACKAGEEditor → 主服务器请求拉取整包
EDITOR_PUSH_PACKAGEEditor → 主服务器推送修改后的整包

6.2 RTC 1.5s 去抖 v2026.06.18

主服务器有任何变更 → 推送 EDITOR_PACKAGE → RTC 收到后不立即应用:

RTC 端:
  收到 EDITOR_PACKAGE → _pendingPackage = package → 启动 1.5s DispatcherTimer
  期间又来新包 → 替换 _pendingPackage, 重置 Timer
  Timer 触发 → 应用最新一份包 (ApplyPackageInMemory)

6.3 编排端身份

Editor 客户端连接后发 {type: "EDITOR_IDENTITY"}, 主服务器立即推一次整包。 RTC 也发此身份 (复用同步链路), 但额外发 TIMING_EXE_IDENTITY。

九、锁机制 (LOCK_*)

9.1 用途

编辑赛程 / 运动员 / 项目时, 同一资源同一时刻只能一个客户端编辑。锁机制防止并发修改冲突。

9.2 消息

消息字段
LOCK_REQUESTcorrId, resource (锁名), timeoutMs
LOCK_REPLYcorrId, granted (true/false), holderName
LOCK_RELEASEresource

客户端断开时主服务器自动释放其所有锁 (ReleaseLocksHeldBy)。

十二、硬件计时器协议

12.1 物理层

方式参数
串口 (UART)9600/8/N/1, ASCII 帧 + 校验
TCP5555 端口, 二进制帧
UDP5002 端口, 二进制帧 (单向广播)

12.2 主要帧 (硬件 → PC)

cmd含义关键字段
0x7F滚动时间 (10Hz)D3..D6 = 时间 ×0.01s
0x16触板事件 (Touchpad / MB 代触)D3=Result type, D4=lane, D5..D8=time, D10 抢跳位
0x17/0x18/0x19盲表 1/2/3 按下D4=lane, D5..D8=time
0x1A出发台 (StartingBlock)D4=lane (低 4 位 side), D5..D8=PreStart 计数器
0x1C仰泳松开同 0x1A 但 D3=3
0x21就位 (Timer_Ready)
0x22发令 (Gun PreStart)D5..D8=Gun_PreStart 计数器
0x64当前参数反馈D3=泳道封闭时间, D4=触板延迟, D5=出发台延迟, D6=盲表代替延迟, D7=成绩显示时间

12.3 主要命令 (PC → 硬件)

cmd含义用途
0x10设发令点 (左/右)StartPosition
0x20清比赛状态
0x21就位PC 软件触发
0x1C发令
0x41设各类延迟时间触板延迟 / 出发台延迟 / 盲表代替延迟 / 成绩显示时间
0x43设比赛事件 (Set_MatchEvent)总圈数 + 左右触板次数 + 空泳道位图
0x44设单/双端触板
0x45设盲表数量D3=左端 D4=右端
0x46设触板/出发台/盲表 启用状态每泳道每端 1 位
0x49/0x4A设盲表 2/3 启用扩展位图
0x42同步 PC 日期+时间到硬件 RTC每 30 分钟周期同步

12.4 硬件 0x16 D3 子类型

D3含义
1 (Touchpad_Result)真触板成绩
2 (Pushbutton_Result)盲表代替触板
3 (BackstrokeRelease)仰泳出发松开

十四、v2026.06.18 协议变更

14.1 新增消息类型

消息用途
RTC_FORWARDRTC → 主服务器, 包装 payload 透传给 display 客户端
TIMING_EXE_IDENTITYRTC 声明自己也是计时 EXE (双重身份)
UPLOAD_AND_PLAY_MEDIA客户端 base64 上传媒体并立即播放

14.2 字段补充

SHOW_*主服务器侧操作员主动切换时加 modeExplicit: true
display.html ?host=URL 参数指定 WebSocket 服务器地址

14.3 行为变更

  • RTC_FORWARD 透传链路: RTC 不开自己的 WebSocket Server, 所有比赛状态经主服务器中转
  • EditorSync 1.5s 去抖: 主服务器 EDITOR_PACKAGE 推送, RTC 端 1.5s 内多次合并为 1 次应用
  • Broadcast 100ms 节流: 事件密集时合并广播 (BroadcastImmediate via DispatcherTimer)
  • 新连客户端: 主服务器 OnOpen 时优先发 _lastRtcSnapshot, 无快照才走 BroadcastSingle
  • 3002 端口冲突探测: RTC 启动前 TcpListener 试绑, 被占即弹框提示
  • 接力反应时窗口启动: 改用基准事件 (TP/MB/手动 TP) 触发, SB 单独到先暂存 (修复抢跳 SB<TP 算不出 bug)
  • 接力反应时窗口时长: 改用 ResultConfirmCloseDelay (默认 3s) 代替原 ReactionEventWindowSec
  • 完赛后 PushButton: 不再被 4595 行早退丢弃, 继续进 ProcessBlindWatchData 存储
  • BroadcastJsonToClients: 统一出口, PUBLISH_RESULT / SHOW_SCHEDULE / SHOW_MEDIA / STAGE_COMPLETE / PROMOTION_DONE / DOC_LIST_RESULT / BroadcastDisplayStyle 都经它处理 RTC/主服务器双模式
