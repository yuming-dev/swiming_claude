硬件计时器待改动需求

v2026.06.06  |  0x16 触板帧 D3 扩展 — 硬件控制盒手动 TP 按钮源标识

背景：2026 年甘肃 U 系列定西站现场实测发现，在某些极端场景下，硬件控制盒 的状态机会卡住等待 TP / MB 信号而不主动换向。临时应急流程已在 PC 端实现（操作员右键 点 PC 该泳道的 T 按钮跳圈，10s 抑制窗口内丢弃硬件随后发的 0x16），但需要操作员 精确按"先点 PC 再按硬件"的顺序操作，且 PC 上的"手动 TP"和"跳圈"两种动作必须通过 "右键单击 vs 1 秒内 2+ 连击" 区分，UX 复杂、易错。

最干净的方案：协议层加一个值区分硬件控制盒的"手动 TP 按钮按下"和"运动员 真实触板"。PC 端按协议自动判断，删掉抑制窗口和右键连击区分。

1. 必修 0x16 Touchpad 帧 D3 字段扩展 — 加 D3=2 表示"硬件手动 TP 按钮"

现状

0x16 触板帧的 D3 字段当前只用两个值：

D3 值含义当前来源
0正常触板信号运动员手 / 脚真实触碰 TP 设备
1盲表代替触板 (MB final / Pushbutton_Result)硬件 BlindReplaceDelay 超时后内部合成

硬件控制盒上有一个"手动 TP"按钮，操作员按下后硬件状态机推进（换向 + 倒计时启动） 并通过 0x16 帧上报。但这种按键产生的 0x16 帧 D3 仍是 0， PC 端无法区分"真触板"和"手动按键"，把手动按键得到的"无意义时间"也当成正式触板成绩记录下来。

现场后果：无 TP / MB 卡住时操作员被迫按硬件手动 TP 键应急 → PC 把当前 _runningTime 记成该圈触板时间 → 大屏出现错误成绩 → 必须事后手工编辑撤销。 影响正式比赛公信力。

修改请求

方向硬件 → PC
命令字节 D20x16 (维持)
D3 新增值2 = 硬件控制盒"手动 TP"按钮触发 本次新增
D4 – D10同现有协议: D4=泳道, D5–D8=时间编码, D9–D10=0

完整 D3 取值表（含新增）：

D3含义PC 端动作
0正常触板正常记 TouchpadTime, 推进状态机
1盲表代替触板 (MB final)记为 MB final 主成绩 (或按 PC 端 "盲表代触板" 开关决定收/丢)
2 新增硬件控制盒手动 TP 按钮只推进状态机, 不记任何时间 (split 空, 等手工补)

修改建议

代码位置APP/swimplay.c 发送 0x16 帧的位置 (现有触板上报路径)
触发条件检测到本次 0x16 上报源于"硬件控制盒手动 TP 按钮"按下，而非真触板 / MB final 超时
需做的事给 TXD_Buffer[3] (D3 字节) 赋 2 而非 0
// 硬件控制盒手动 TP 按钮按下分支:
TXD_Buffer[3] = 2;   // D3 = 硬件手动按键源标识
TXD_Buffer[4] = lane;
// D5..D8 时间编码同正常 (= 当前 RunningTime, 哪怕 PC 不记也保留留痕)
SendFrame_0x16(...);

// 真触板 (TP 设备物理触发) 分支保持现有逻辑:
TXD_Buffer[3] = 0;

// MB final 代替分支保持现有逻辑:
TXD_Buffer[3] = 1;
时间字段 D5–D8 仍要填：即使 PC 不会把这个时间作为成绩，仍建议硬件填入按键时刻 的 RunningTime，便于调试/留痕（PC 会把它写入原始计时日志，标 "TouchpadHwManual"， 但不计入 split.TouchpadTime）。

PC 端配合

2. 兼容性 旧硬件 / 新硬件 共存

硬件版本0x16 帧 D3PC 端行为
旧固件 (本次改动前)只发 0 或 1D3=0 正常 TP, D3=1 MB final — 与现有逻辑相同, 不影响
新固件 (本次改动后)0 / 1 / 2 三种D3=0/1 同前, D3=2 走 ProcessSkipLapAdvanceOnly

PC 端只需新增 D3=2 分支，D3=0/1 路径完全不变。旧硬件升级前一直按现有逻辑工作， 升级后自动启用新流程，零迁移成本。

3. 协议版本号 文档更新

修改完成后请同步更新 docs/游泳计时系统通讯协议_v2026.xx.html 4.1 节 (0x16 / 0x17 / 0x18 / 0x19 触板与盲表) 的 D3 字段说明:

原:
  D3   子码（保留 0）

改:
  D3   子码: 0=正常触板 / 1=盲表代替 (MB final) / 2=硬件控制盒手动 TP 按钮 (PC 不记时间)

4. 测试建议

测试 1: 手动 TP 按键正确产生 D3=2

  1. PC 进入比赛 Ready 状态, 启动计时
  2. 在硬件控制盒上按"手动 TP"按钮 (针对某一泳道)
  3. 用 wireshark 或 PC 串口日志看捕获的帧, 应为:
    F1 53 16 02 LL DD DD DD DD 00 00 F4 (D3=0x02)
  4. PC 端日志应出现 泳道N 硬件手动 TP 按钮 → 跳圈 (不记时间)
  5. 该泳道在 PC UI / 大屏上: 圈数减 1, 方向翻转, 该段 split 显示空白
  6. 到"成绩与排名"页面 → 该段时间为空, 等手工输入

测试 2: 真触板仍走 D3=0 路径

  1. 运动员真实触碰 TP 设备 → 硬件应发 D3=0 (= 维持原行为)
  2. PC 端 split.TouchpadTime 应正常记录
  3. 大屏正常显示成绩

测试 3: MB final 仍走 D3=1 路径

  1. 运动员未触 TP 但盲表有按下 → 硬件 BlindReplaceDelay 超时后发 D3=1
  2. PC 端按 "盲表代触板" 开关决定收 / 丢 (现有逻辑)
  3. 不应误判为 D3=2

5. 背景信息 当前 PC 端应急方案

固件修复前, PC 端 (v2026-06-06) 已部署应急方案:

机制说明位置
右键单击 T 跳圈操作员主动告知 PC "我要跳圈"OnTButtonRightClick, count == 1
右键 1s 内 2+ 连击 = 手动 TP区分跳圈和真"手动 TP 记当前时间"OnTButtonRightClick, count >= 2
左键禁用防误操作 (= 比赛中误碰 T 不再触发 TP)touchL/R.PreviewMouseLeftButtonDown
10s 硬件 0x16 抑制窗口操作员按 PC 跳圈后, 紧跟按硬件键产生的 0x16 自动丢_skipNextHwTpUntil 字典

应急方案的缺点 (= 本协议改动后可全部消除):

  • 操作员必须严格"先 PC 右键、后硬件键"顺序, 反向时 PC 仍记错时间
  • 右键单击有 1 秒延迟才推进 (= 等待是否续击区分)
  • 左键被禁用, 手动 TP 必须双击右键, 紧急情况下操作慢
  • 10s 抑制窗口是经验值, 若硬件 0x16 在 11s 后才到则误记
固件支持 D3=2 后, PC 端只保留:
  • T 按钮 左键 = 手动 TP (记当前时间) — 恢复直观操作
  • 硬件按 D3=2 自报 → PC 自动跳圈, 不需要操作员任何配合点击
  • 删掉 _skipNextHwTpUntil / _tpRightClickCount / _tpRightClickTimer / OnTButtonRightClick 全部应急代码
