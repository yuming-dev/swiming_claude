游泳计时通讯协议变更说明

v2026.06.06 (相对 v2026.05.20 增量)

本期变更总览

类别项类型
WebSocket 命令EXPORT_RESULT_TXT_LIST / EXPORT_RESULT_TXT_BUILD新增 (control.html ↔ 服务器)
WebSocket 响应EXPORT_RESULT_TXT_LIST_RESP / EXPORT_RESULT_TXT_FILE新增 (服务器 → control.html)
广播数据字段applicableRecords (项目纪录数组)新增 (SHOW_LIVE_RACE / SHOW_PUBLISHED_RESULT 携带)
广播数据字段swimmer.gender / swimmer.ageGroup / swimmer.recordNote新增 (公布成绩广播)
JSON SchemaCompetitionRule / ScheduleItem.EvNum新增字段
硬件协议无变更—

一、新增 WebSocket 命令

1. EXPORT_RESULT_TXT_LIST 新

方向: control.html → 服务器

{
  "type": "REMOTE_CONTROL",
  "command": "EXPORT_RESULT_TXT_LIST"
}

请求已完赛组次列表 (用于浏览器侧弹窗展示)。

2. EXPORT_RESULT_TXT_LIST_RESP 新

方向: 服务器 → control.html (响应 #1)

{
  "type": "EXPORT_RESULT_TXT_LIST_RESP",
  "heats": [
    {
      "ageGroup": "12-13岁组",
      "gender": "男",
      "eventName": "50米自由泳",
      "stage": "决赛",
      "heat": 1,
      "session": 2,
      "eventNo": 8,
      "fileName": "02-08-01.txt",
      "title": "12-13岁组 男 50米自由泳 决赛 第1组"
    },
    ...
  ]
}

遍历 _confirmedHeats 集合, 每条 key 解析回 (ageGroup|gender|event|stage|heat)。

3. EXPORT_RESULT_TXT_BUILD 新

方向: control.html → 服务器 (用户在弹窗点击某组次后)

{
  "type": "REMOTE_CONTROL",
  "command": "EXPORT_RESULT_TXT_BUILD",
  "data": {
    "ageGroup": "12-13岁组",
    "gender": "男",
    "eventName": "50米自由泳",
    "stage": "决赛",
    "heat": 1
  }
}

请求构建该组成绩 txt 文件内容并下发给浏览器。

4. EXPORT_RESULT_TXT_FILE 新

方向: 服务器 → control.html (响应 #3)

{
  "type": "EXPORT_RESULT_TXT_FILE",
  "content": "01 00:00.00 ...\n02 00:25.88 00:25.88 0001.05\n...",
  "fileName": "02-08-01.txt"
}

或失败:

{
  "type": "EXPORT_RESULT_TXT_FILE",
  "error": "异常消息"
}

浏览器收到后 Blob.download 触发文件下载。

二、广播数据扩展

1. applicableRecords 新

携带场景: 主广播 GetStatusData() (SHOW_LIVE_RACE 等) + PublishResultToDisplay() (SHOW_PUBLISHED_RESULT)

"applicableRecords": [
  {
    "tag": "MR",                  // 由 RecordTypeToTag 转: 甘肃省纪录 → MR
    "ageGroup": "14-15岁组",
    "gender": "男",
    "time": "00:33.01",
    "holderName": "张某某"
  },
  { "tag": "MR", "ageGroup": "14-15岁组", "gender": "女", "time": "00:35.22", "holderName": "李某" }
]

过滤逻辑: 按 (eventName, gender, ageGroup) 三维过滤:

  • gender = "男女" → 同时包含 男 / 女 / 男女 三类记录
  • ageGroup 非空 → 用 MatchesAgeGroup 区间匹配 (含 "12~15" ⊇ "12-13"+"14-15")
  • 排序: RecordType 优先级 (WR > OR > AR > AJR > NR > MR > 市R > CR) + 年龄组注册顺序

display.html 在 比赛视图 / 组成绩 / 公布成绩 / 总排名 4 个视图的项目名称下渲染 inline 金色虚线行。

2. swimmer.gender 新

per-swimmer 字段添加, 用于 display.html 大屏分段标签 (虽然 U 系列规则下组内单一排名后已不再需要分段)。

3. swimmer.ageGroup 新

per-swimmer (= swimmer.AgeCategory) 携带, 公布成绩广播之前 缺失, 现补齐。

4. swimmer.recordNote 新

per-swimmer 的破/平纪录标识 ("MR" / "=MR" / "WR/MR" 等), 公布成绩广播之前缺失, 现补齐。

三、JSON Schema 扩展

1. CompetitionPackage.CompetitionRule 新

"CompetitionRule": "U系列青少年游泳比赛"

取值: "国际比赛" / "国内大赛" / "U系列青少年游泳比赛" (默认)

2. ScheduleItem.EvNum 新

{
  "SessionNumber": 2,
  "EvNum": 11,                  // 项次 (按场重置 1-N)
  "AgeGroup": "16-18岁组",
  "EventName": "50米蛙泳",
  "Gender": "男女",
  "Stage": "决赛",
  ...
}

从原始 .xls 秩序单的 "N . XXX" 直接读取, 按场重置。如缺失 (EvNum=0), BuildEventNumberMap 回退到跨场连续编号。

3. RelayTeam.Members 类型保持兼容

修复: import_v4 之前误写为 string[], 与 C# ObservableCollection<Swimmer> 不兼容, 导致加载赛事崩溃。现 Members 留空 [], 4 棒姓名转 Legs: [RelayLeg] 对象。

四、男女并项 (U系列规则) 影响

schedule.Gender = "男女"

schedule 项目 Gender 可为 "男女" (除原有 "男" / "女" / "混合" 外)。表示该项目允许男女在同组比赛。

swimmer.Gender 不变

个人 swimmer 的 Gender 仍是真实的 "男" / "女"。仅接力队 TEAM swimmer 条目 Gender 可为 "男女" (整队作一条 swimmer)。

SgMatch / GenderMatchesIncludingMixed 助手

新增 SgMatch(swimmerGender, filterGender):

  • filterGender == "男女" → swimmerGender ∈ {"男", "女", "男女"} 都过
  • 其它 → 严格相等

用于 30+ 个原本严格相等的 lookup 点 (出发表, 组成绩, 总排名, heat 切换, 报名查询 等)。

MatchesAgeGroup 区间

schedule.AgeGroup 可为区间 "12~15岁组" (含半角 ~ / 全角 ～):

// 通过 swimmer.AgeCategory ∈ {12-13岁组, 14-15岁组} 都算属于 "12~15岁组"
TryParseAgeRange("12~15岁组")  → [12, 15]
TryParseAgeRange("12-13岁组")  → [12, 13]
gLo (12) ≤ sLo (12) && sHi (13) ≤ gHi (15) → match

五、CheckRecords 修复 (关键)

重要: 男女并项事件下破纪录之前漏检。

旧: record.Gender != _currentGender — 男女并项时 _currentGender = "男女", 永远不匹配 "男" / "女" 记录, 19 个并项项目的所有破纪录都不被识别。

新: 用 swimmer.Gender (单一性别) 对比 record.Gender:

string swGender = swimmer.Gender ?? "";
foreach (var record in _records) {
    if (record.Gender != swGender) continue;
    ...
}

同款修复:

  • UpdateRecordsAfterConfirm (line 5717)
  • LookupRecordReferences (line 19866): gender=="男女" 时返回 男+女+男女 三类

六、DSQ 分类清除 (新规则) 新

个人项目 DSQ:

res.Splits.Clear();
res.FinalTime = 0;
res.TimeInSeconds = 0;
res.StartingBlockTime = 0;

接力项目 DSQ (需要弹窗选犯规棒次 N):

// 解析 perLegMeters from EventName (4x50米 → 50; 4x100米 → 100)
int keepDist = (violationLeg - 1) * perLegMeters;
// 保留 Distance ≤ keepDist 的分段, 清其余
res.Splits.RemoveAll(sp => sp.Distance > keepDist);
// 清第 N 棒及之后的反应时
res.LegReactionTimes[N-1..] = 0;
res.FinalTime = 0;

七、BuildEventNumberMap 改进

之前 keyed by (Gender|EventName) 2 维 + 跨场连续编号。

新: 优先 ScheduleItem.EvNum, fallback 才计数:

foreach (var s in _schedule) {
    string key3 = $"{s.Gender}|{s.EventName}|{s.AgeGroup}";  // 3 维
    int num = (s.EvNum > 0) ? s.EvNum : ++fallbackN;
    map[key3] = num;
    // 兼容旧 2-part key (调用方可能用)
    string key2 = $"{s.Gender}|{s.EventName}";
    if (!map.ContainsKey(key2)) map[key2] = num;
}

八、性能优化

BuildScheduleTree

1122 swimmer × 78 项目 时 IsHeatConfirmed 每次都对全部 _swimmers 做 Where 遍历, 234 次 heat check = 262K 次迭代。

新增 IsHeatConfirmedFast(..., Dictionary<string, List<Swimmer>> idx) 重载, 函数开头一次性构建 EventName → swimmers 索引。80× 加速。

RefreshSwimmerStages

同款: 1122 × 78 = 87K → 6.7K。13× 加速。

九、display.html 渲染兼容

男女并项 不再拆段

之前组内按 (性别, 时间) 二级排序, 显蓝/粉分段标签。现按 U 系列规则: 组内单一排名按时间。display.html 的 renderHeatResult / renderPublishedResult / showHeatResultPage 均回退到 (a.rank||99) - (b.rank||99) 单键排序, 无分段。

项目名称下 MR 行

新增 #applicableRecordsRow div 在 raceView 内, 由 _renderApplicableRecords(records) 渲染:

<div class="ar-item">
  <span class="ar-tag">MR14-15</span>
  <span class="ar-time">00:33.01</span>
</div>

代表队列显中文全名

修复: _refreshRaceRows 之前 sw.countryShort || sw.country 优先英文短码 (TTYYD); 现 sw.country || sw.countryShort 优先中文 (天体游泳队)。
