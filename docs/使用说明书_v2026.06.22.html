1.2 三种工作模式

核心规则：三个"计时控制端"(主服务器 / RTC.exe / race_control.html) 哪个直连硬件计时器, 哪个就是计时主控, 其他端只能观察, 不能反控。
主控选择典型场景消息流
主服务器直连硬件小型比赛, 单 PC 部署硬件 ←→ 主服务器 → display.html (直接)
RTC.exe 直连硬件大型比赛, 计时席与编排席分开硬件 ←→ RTC → 主服务器 → display.html

1.3 部署架构示意

2.2 启动顺序 (强烈建议)

  1. 主服务器 PC: 管理员身份运行 SwimmingScoreboard.exe (首次需 admin 给 HTTP 8080 注册 URL ACL)
  2. 主服务器登录 (admin/admin 默认), 在"赛事管理"载入比赛档案 (.json)
  3. RTC PC: 运行 RemoteTimingControl.exe, 顶栏填主服务器 IP, 点"连接"
  4. RTC 通过"参数设置 → 硬件计时器连接"配置硬件 (TCP/UDP/串口)
  5. RDC PC: 运行 RemoteDisplayControl.exe, 填主服务器 IP, 点"连接", 左侧 WebView2 自动加载大屏预览
  6. 大屏 PC: 浏览器打开 http://主服务器IP:8080/display.html
  7. 其他客户端: control.html / race_control.html / query.html / checkin.html 同样从主服务器 8080 取
注意: 主服务器和 RTC.exe 不能在同一台 PC 上运行 (3002 端口冲突)。RTC 启动时会探测 3002, 若被占自动弹框提示"端口冲突 — 请关闭主服务器或将 RTC 部署到另一台 PC"。

三、网络架构与端口

3.1 端口使用

端口用途提供方
3002 (TCP, WebSocket)消息总线 / 实时数据广播主服务器 (主控模式) — RTC 不开
8080 (HTTP)Web 文件服务 — 提供 display.html / control.html / race_control.html / query.html 等主服务器
硬件 TCP 5555 / UDP 5002 / 串口与硬件计时器通信主控 (主服务器或 RTC)

3.2 防火墙

主服务器需放行 TCP 3002 和 TCP 8080 入站。首次以管理员启动会自动尝试注册 URL ACL, 失败时降级到 localhost:8080 仅本机访问。

3.3 多机部署

典型部署: 主服务器 1 台 + RTC 1 台 + RDC 多台 + 大屏 1-N 台 + 查询终端 0-N 台。所有客户端都连主服务器的 3002 端口。 RTC 是唯一连硬件计时器的端点。

v2026.06.19 现场实测: 硬件 TCP 链路下硬件开始送时间帧后, HTML 客户端 (query/display/race_control) 出现全 0/闪烁/调不到数据。 切换 RS232 即正常。大型比赛建议优先 RS232, TCP 链路问题待固件层后续修复。

四、赛事管理与报名 (ScheduleEditor)

4.1 创建比赛档案

主服务器或 ScheduleEditor 中"新建比赛":

  • 填写比赛名称 / 日期 / 场馆 / 泳池配置 (25m/50m, 道数)
  • 选择适用规则 (U系列 / 标准 / 自定义)
  • 保存为 .json 比赛档案到 Database/

4.2 项目编排

在"项目管理"中:

  • 添加项目: 男子/女子, 距离, 泳姿, 阶段 (预赛/半决赛/决赛/A组/B组)
  • 设置项目顺序 (SessionNumber / EvNum)
  • 关联接力 (4×50 / 4×100 / 4×200 等)
  • 批量导入: 从 Excel 模板粘贴

4.3 运动员报名

三种方式:

  1. 主服务器: 报名 tab 单条录入
  2. RegistrationTool.exe: 批量导入运动员 (CSV / 模板)
  3. register.html: Web 端报名 (远程报名)

4.4 赛程编排

"赛程编排" tab:

  • 按项目自动分组 (HeatScheduler 算法)
  • 道次自动分配 (蛇形 / 中间向外)
  • 手动调整道次 + 撤销 / 重排

4.5 同步到主服务器

ScheduleEditor 顶栏填主服务器 IP, 点"连接":

  • 连接成功后, 主服务器自动推送整包 (EDITOR_PACKAGE) 给编排端
  • 编排端修改后自动回推主服务器 (EDITOR_PUSH_PACKAGE)
  • 主服务器侧推回各客户端时, RTC 端有 1.5s 去抖, 避免频繁全量重建

4.6 兼容其他厂家成绩编排软件 v2026.06.21 新增

为兼容其他厂家成绩编排软件输出的 Excel, 赛程管理新增 2 个导入按钮 (拆到单独行避免挤出可视区):

  • 导入 (其他) 日程表: 读 9 列 .xlsx 格式 (场次/时间/编号/性别/组别/项目/赛次/人(队)数/组数), 按 (性别+组别+项目+赛次) 反查 _schedule: 找到 → 更新; 找不到 → 新增. 追加模式不破坏已有数据.
  • 导入 (其他) 分组表: 读网格式 .xlsx (项目 block + 组号 × 道次 × 2 行: 姓名+单位), 按 (姓名+单位+项目+性别) 反查 _swimmers: 找到 → 更新 Heat/Lane/CurrentStage; 找不到 → 新增 (BibNumber 自动续). 可多次叠加导入, 兼容已有报名.

运动员管理 tab 同步新增:

  • 导入 (其他) 运动员信息 v2026.06.21: 从单项明细 .xls/.xlsx 导入运动员, 格式: R1 大标题, R2 表头 (开赛日期/场次/项次/组号/道次/性别/组别/距离/姿式/赛别/单位简称/运动员/证件编号/出生日期/电话/年龄 等 33 列), R3 起数据. 无"距离+姿式" (= 无项) 的行忽略. 反查策略: 姓名+证件号 (强匹配) 或 姓名+单位+项目+性别 (弱匹配). 找到 → 更新元数据 (空值不覆盖); 找不到 → 新增.
注意: .xls (BIFF) 老格式 NPOI 在某些文件有兼容性 bug, 失败提示用户先用 Excel 另存为 .xlsx 再导入。

4.7 赛程管理日程表显示"人(队)数"列 v2026.06.21

赛程管理右侧 DataGrid 显示日程表, 列顺序: 时间 / 组别 / 性别 / 项目 / 阶段 / 人(队)数 / 组数。 "人(队)数" 列按 (Gender, EventName, AgeGroup, Stage) 反查 _swimmers 实时计数。

5.1.1 ♻ 释放内存按钮 v2026.06.20 新增

顶端"内存"数字右侧的 [♻ 释放] 蓝色按钮 (PC/RTC/race_control 三端都有):

  • 本地按按钮: 弹窗显示前/后/释放 MB
  • race_control 远程按: 通过 RELEASE_MEMORY 命令触发, 静默执行
  • 触发动作: 强制 GC (Collect → WaitForPendingFinalizers → Collect) + SetProcessWorkingSetSize(-1,-1) 压最小
  • 大堆下可能短暂卡顿 (用户主动触发可接受)
  • 不能释放其他进程内存 (Windows 进程隔离)

5.2 比赛状态机

5.6 颁奖按钮 v2026.06.21 重设计

原 "颁奖" 按钮直接发布当场比赛, 现改为弹窗选项目回放:

  1. 按 "颁奖" 按钮 → 弹出 "选择颁奖项目" 窗口
  2. 列出所有已完赛 (Stage=决赛 + 所有组都已 '确认本组成绩') 项目
  3. 显示格式: [组别] 性别 项目 决赛 (X 人 X 组 全部已确认), 默认选第 1 项
  4. 按 "确认 → 大屏颁奖": 服务器记 _awardSelection, 推 SHOW_AWARDS
  5. 大屏 display.html 按选定项目的全项目总排名前 3 名颁奖 (银/金/铜领奖台)
  6. 按 "取消": 不动作, 大屏保持当前状态
  7. 切换到其他大屏模式 → 自动清 _awardSelection
关键: 多组决赛的颁奖按整个项目所有完赛运动员的总排名前 3, 不是单组前 3.

七、比赛规则 (U系列 / 男女并项)

7.1 U系列规则

U10 / U12 / U14 / U16 等青少年组别:

  • 按出生年份自动分组
  • 支持 U 全级别混合 / 跨级别预决合并
  • 报名时输入"年龄组"字段, 系统自动按规则归类

7.2 男女并项

同一项目可设男女并项 (混合编排成绩仍分开统计):

  • 分配道次时男女合一
  • 比赛中显示 M/F 标识
  • 成绩页和颁奖分别处理

八、接力比赛与反应时

8.1 接力项目编排

项目名包含 "4×50" / "4×100" 即识别为接力:

  • 每队 4 名队员, 按棒次填写
  • 每棒长度 = 总距离 ÷ 4 (= perLegLaps × 泳池长度)

8.2 第 1 棒反应时 (个人出发反应)

枪响 (0x22 PreStart) → 出发台离开 (0x1A SB) → 反应时 = SB_PreStart - Gun_PreStart。负值 = 抢跳。

8.3 第 2/3/4 棒反应时 (接力交接)

算法 (RelayReactionCalculator):

  1. 每 (lane, side) 一个独立窗口, 窗口时长 = ResultConfirmCloseDelay (默认 3s)
  2. 窗口由基准事件 (TP / MB_FirstPress / MB_Final / 手动 TP) 触发
  3. SB 单独到时若无窗口, 暂存到 _pendingSbs, 等基准事件触发窗口后取出
  4. 窗口到期: reaction = LastSbSwim - basis, basis 优先级 TP > MB_Final > 手动 TP
  5. reaction > 0 = 正常反应时, reaction < 0 = 抢跳 (标记 IsSuspectFalseStart)

8.4 接力交接犯规

反应时 < FalseStartThreshold (默认 0s) 即视为可疑抢跳, 标红字段, 等裁判确认。

8.5 仰泳协议彻底重构 v2026.06.22 重大修复

修复用户报"100m+ 仰泳运动员到终点 (出发端=终点端) 没成绩"严重 bug:

根因

固件原行为与 PC 端协议预期完全相反:

事件PC 协议期望固件原实际
TP 按下 (0→1, 预备脚踩)不发任何帧发 D3=3 BackstrokeRelease ❌ 位置错
TP 松开 (1→0, 出发蹬出)发 D3=3 + 不减圈发 D3=0 Touchpad + 减 1 圈 ❌ 协议错

导致: 仰泳出发瞬间 (TP 松开) 被硬件当成正常触板减圈, 100m 仰泳 totalLaps=2 第 1 圈被错占, 50m 时硬件认为已完赛 → 提前关闭终点 TP → 100m 真终点触板被丢 → 没成绩.

修复 (固件 swimplay.c, 6 处改动)

  1. TP 松开路径 (line 4710/4837): 加 BackstrokeBit 守卫
    • 仰泳出发瞬间 (BackstrokeBit=1 + Ready_timer_bit=1 + GunFired_PostOpenDoneBit=0): 发 D3=3 BackstrokeRelease + 缓存反应时锚点, 不减圈
    • 其他场景 (真实终点触板 / 非仰泳): 发 D3=0 + 正常减圈
  2. TP 按下路径 (line 4756/4870): 原发 BackstrokeRelease 逻辑用 if (0) {...} 禁用 (位置错, 预备踩不该发任何帧)
  3. 反应时"覆盖迭代": 每次 TP 松开都覆盖 PreStart_minute/second/msecond + Valid=1, 取最新一次蹬出时刻

测试验证

  • 100m 仰泳 (50m 池, 核心场景): 出发→50m 触右→100m 触左能拿成绩
  • 200m / 400m 仰泳: 多圈不减错
  • 50m 仰泳: 出发端 ≠ 终点端, 守卫不误伤
  • 100m 自由泳/蛙泳/蝶泳 (BackstrokeBit=0): 守卫不触发, 减圈和 D3=0 不受影响
PC 端 case "Touchpad" 仰泳出发端守卫 (CurrentLap=0) 仍保留作 defense-in-depth (固件未修协议或回滚时的兜底)。

十四、故障排查

14.1 RTC 启动报"端口冲突"

原因: 同一台 PC 跑了主服务器 (占 3002)。解决:

  • 关闭本机已运行的 SwimmingScoreboard.exe; 或
  • 把 RTC 部署到另一台 PC

14.2 比赛中 HTML 客户端 (query/display/race_control) 全 0 / 闪烁 / 调不到数据 v2026.06.19 实测

用户实测: 硬件 TCP 链路下开始送时间帧后会污染 PC → HTML 客户端全 0 / 闪烁 / 数据缺失。

立即解决: 切换硬件为 RS232 即正常。TCP 链路 fundamentally 修复待固件后续。

14.3 100m+ 仰泳到终点没成绩 v2026.06.22 已修复

原因: 固件原协议错位, 仰泳出发 TP 松开发 D3=0 + 减圈, 50m 时硬件认为完赛提前关 TP。 v2026.06.22 固件 swimplay.c 6 处改动彻底重构协议. 需重新烧录固件。

14.4 反应时显示 "---"

v2026.06.20 加反应时收集窗口: 发令后 ReactionEventWindowSec 秒 (默认 3s) 未收到合法 SB → 标 "---"。 原因可能:

  • 该泳道出发台未安装 (设备状态管理设为"未安装")
  • 硬件 0x1A SB 帧时间字段=0 (无有效信号)
  • 该泳道被标 DNS / DNF

14.5 接力反应时显示"---"

  • "反应时间检测"参数是否开启 (ReactionTimeEnabled)
  • 该泳道是否被标 DNS / DNF
  • 硬件 SB 是否真发出 (查比赛日志 "出发台" 条目)

14.6 主服务器修改后 RTC 没同步

加了 1.5s 去抖 (合并多次推送), 等 1.5s 即可。 若超过 1.5s 仍未变化, 检查 RTC 顶端"主服务器"状态是否"已连接" (绿)。

14.7 滚动时间跳跃 / UI 卡顿

  • 检查内存监控 (顶端右侧), > 80% 可能 GC 频繁, 按 [♻ 释放] 试试
  • 关闭无用客户端 (display.html / race_control.html 多个窗口同时连)
  • 检查网络 — 无线弱信号会导致 WebSocket 包延迟

14.8 display.html 不显示运动员

  • RTC 模式下: 检查 RTC 是否选中某组 (左侧赛程导航)
  • 新连接的 display 应该立即收到最近一帧快照 (主服务器 _lastRtcSnapshot)
  • 若 RTC 未发过任何状态, 主服务器无快照可发, 选组后即恢复
