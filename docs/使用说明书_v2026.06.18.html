1.2 三种工作模式 v2026.06.18 重要

核心规则：三个"计时控制端"(主服务器 / RTC.exe / race_control.html) 哪个直连硬件计时器， 哪个就是计时主控，其他端只能观察，不能反控。

2.2 启动顺序 (强烈建议)

  1. 主服务器 PC：管理员身份运行 SwimmingScoreboard.exe (首次需 admin 给 HTTP 8080 注册 URL ACL)
  2. 主服务器登录 (admin/admin 默认), 在"赛事管理"载入比赛档案 (.json)
  3. RTC PC：运行 RemoteTimingControl.exe, 顶栏填主服务器 IP, 点"连接"
  4. RTC 通过"参数设置 → 硬件计时器连接"配置硬件 (TCP/UDP/串口)
  5. RDC PC：运行 RemoteDisplayControl.exe, 填主服务器 IP, 点"连接", 左侧 WebView2 自动加载大屏预览
  6. 大屏 PC：浏览器打开 http://主服务器IP:8080/display.html
  7. 其他客户端：control.html / race_control.html / checkin.html 同样从主服务器 8080 取
注意：主服务器和 RTC.exe 不能在同一台 PC 上运行 (3002 端口冲突)。RTC 启动时会探测 3002, 若被占自动弹框提示"端口冲突 — 请关闭主服务器或将 RTC 部署到另一台 PC"。

2.3 凭据管理

三、网络架构与端口

3.1 端口使用

端口用途提供方
3002 (TCP, WebSocket)消息总线 / 实时数据广播主服务器 (主控模式) — RTC 不开
8080 (HTTP)Web 文件服务 — 提供 display.html / control.html / race_control.html 等主服务器
硬件 TCP 5555 / UDP 5002 / 串口与硬件计时器通信主控 (主服务器或 RTC)

3.2 防火墙

主服务器需放行 TCP 3002 和 TCP 8080 入站。首次以管理员启动会自动尝试注册 URL ACL, 失败时降级到 localhost:8080 仅本机访问。

3.3 多机部署

典型部署: 主服务器 1 台 + RTC 1 台 + RDC 多台 + 大屏 1-N 台。所有客户端都连主服务器的 3002 端口。 RTC 是唯一连硬件计时器的端点。

四、赛事管理与报名 (ScheduleEditor)

4.1 创建比赛档案

主服务器或 ScheduleEditor 中"新建比赛":

  • 填写比赛名称 / 日期 / 场馆 / 泳池配置 (25m/50m, 道数)
  • 选择适用规则 (U系列 / 标准 / 自定义)
  • 保存为 .json 比赛档案到 Database/

4.2 项目编排

在"项目管理"中:

  • 添加项目: 男子/女子, 距离, 泳姿, 阶段 (预赛/半决赛/决赛/A组/B组)
  • 设置项目顺序 (SessionNumber / EvNum)
  • 关联接力 (4×50 / 4×100 / 4×200 等)
  • 批量导入: 从 Excel 模板粘贴

4.3 运动员报名

三种方式:

  1. 主服务器: 报名 tab 单条录入
  2. RegistrationTool.exe: 批量导入运动员 (CSV / 模板)
  3. register.html: Web 端报名 (远程报名)

4.4 赛程编排

"赛程编排" tab:

  • 按项目自动分组 (HeatScheduler 算法)
  • 道次自动分配 (蛇形 / 中间向外)
  • 手动调整道次 + 撤销 / 重排

4.5 同步到主服务器

ScheduleEditor 顶栏填主服务器 IP, 点"连接":

  • 连接成功后, 主服务器自动推送整包 (EDITOR_PACKAGE) 给编排端
  • 编排端修改后自动回推主服务器 (EDITOR_PUSH_PACKAGE)
  • 主服务器侧推回各客户端时, RTC 端有 1.5s 去抖, 避免频繁全量重建

八、接力比赛与反应时

8.1 接力项目编排

项目名包含 "4×50" / "4×100" 即识别为接力:

  • 每队 4 名队员, 按棒次填写
  • 每棒长度 = 总距离 ÷ 4 (= perLegLaps × 泳池长度)

8.2 第 1 棒反应时 (个人出发反应)

枪响 (0x22 PreStart) → 出发台离开 (0x1A SB) → 反应时 = SB_PreStart - Gun_PreStart。负值 = 抢跳。

8.3 第 2/3/4 棒反应时 (接力交接) v2026.06.18 修复

新算法 (RelayReactionCalculator):

  1. 每 (lane, side) 一个独立窗口, 窗口时长 = ResultConfirmCloseDelay (默认 3s)
  2. 窗口由基准事件 (TP / MB_FirstPress / MB_Final / 手动 TP) 触发
  3. SB 单独到时若无窗口, 暂存到 _pendingSbs, 等基准事件触发窗口后取出
  4. 窗口到期: reaction = LastSbSwim - basis, basis 优先级 TP > MB_Final > 手动 TP
  5. reaction > 0 = 正常反应时, reaction < 0 = 抢跳 (标记 IsSuspectFalseStart)
修复点: 抢跳场景 (SB 早于 TP) 不再因 SB 先触发窗口而丢失 TP 基准, 反应时正确计算为负值。

8.4 接力交接犯规

反应时 < FalseStartThreshold (默认 0s) 即视为可疑抢跳, 标红字段, 等裁判确认。

九、TRI / DSQ / DNS / DNF / 抢跳

9.1 状态标记

标记含义处理
TRI三项标记 (人工标记)导出三项标识
DSQ取消比赛资格 (规则违反)仍记录成绩, 大屏不显示, 排名跳过
DNS未起跳 (Did Not Start)整道关闭, 不接收数据
DNF未完赛 (Did Not Finish)记录已完成分段, 大屏标 DNF
抢跳 DSQ反应时为负 + 裁判判罚水中仍接收数据 (保留分段记录)

9.2 抢跳处理流程

  1. 反应时 < 阈值 → 自动标 IsSuspectFalseStart=true (反应时红字)
  2. UI 提示 "⚠ 起跳可疑"
  3. 运动员继续比赛, 触板 / 盲表数据照常记录
  4. 赛后裁判通过 "标 DSQ" 按钮确认是否判罚

十、成绩处理与发布

10.1 成绩确认 (ConfirmResult)

比赛 Finished 后:

  • 各泳道成绩按"计时源裁定" (TP > MB > 手动) 算出 FinalTime
  • 裁判可手动调整 / 标记 / 撤销
  • "确认成绩"按钮触发: _confirmedHeats 添加该组, 落盘比赛档案, 印小条

10.2 成绩发布到大屏

"成绩发布"按钮 (主服务器 / RDC / control.html):

  • 列出所有已确认完赛的组 (按 ageGroup | gender | event | stage | heat 筛选)
  • 选定后发 PUBLISH_RESULT 命令, 主服务器构建数据后广播给所有 display
  • v2026.06.18 加 ageGroup 字段, 修跨年龄段污染

10.3 排名 / 团体 / 颁奖

  • 组成绩 (Heat Result): 该组完赛排名
  • 总排名 (Event Ranking): 整个项目所有组的总排名
  • 团体积分: 按总排名 ×积分表 累计单位
  • 颁奖: 前 N 名 + 音效 + 大屏

十三、故障排查

13.1 RTC 启动报"端口冲突" v2026.06.18

原因: 同一台 PC 跑了主服务器 (占 3002)。解决:

  • 关闭本机已运行的 SwimmingScoreboard.exe; 或
  • 把 RTC 部署到另一台 PC

13.2 RDC 预览"无法访问页面"

v2026.06.18 默认用 file:/// 本地加载 display.html, 不依赖 8080。若仍失败:

  • 检查 RDC 安装目录有 Web/display.html 文件
  • 检查客户机已装 WebView2 Runtime (Edge 装了就有, Win10/11 多数预装)
  • 右下"未连接": 顶端"服务器"框填主服务器 IP 重连

13.3 接力反应时显示"---"

v2026.06.18 前: 抢跳时 SB 先到, TP 在 3s 窗口外才到, 反应时算不出。v2026.06.18 已修复 (基准事件触发窗口)。 若新版本仍出现 "---", 检查:

  • "反应时间检测"参数是否开启 (ReactionTimeEnabled)
  • 该泳道是否被标 DNS / DNF
  • 硬件 SB 是否真发出 (查比赛日志 "出发台" 条目)

13.4 主服务器修改后 RTC 没同步

v2026.06.18 加了 1.5s 去抖 (合并多次推送), 等 1.5s 即可。 若超过 1.5s 仍未变化, 检查 RTC 顶端"主服务器"状态是否"已连接" (绿)。

13.5 滚动时间跳跃 / UI 卡顿

v2026.06.18 加了 100ms 节流, 大幅减少 UI 线程压力。若仍卡顿:

  • 检查内存监控 (顶端右侧), > 80% 可能 GC 频繁
  • 关闭无用客户端 (display.html / race_control.html 多个窗口同时连)
  • 检查网络 — 无线弱信号会导致 WebSocket 包延迟

13.6 display.html 不显示运动员

  • RTC 模式下: 检查 RTC 是否选中某组 (左侧赛程导航)
  • 新连接的 display 应该立即收到最近一帧快照 (主服务器 _lastRtcSnapshot)
  • 若 RTC 未发过任何状态, 主服务器无快照可发, 选组后即恢复
