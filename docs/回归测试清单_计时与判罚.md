# 回归测试清单 — 计时 / 判罚 / 确认成绩

2026-09-13 建。这条链上 2026-09-12~13 两天连出五个 bug，全都是"数据对、显示不对"
或"这台对、那台不对"，靠现场撞代价太大。改动只要碰到下面任何一处，照着走一遍。

约定：**每一步都要三处一起看** —— 计时端界面中间那块泳道面板、大屏、主服务器
「系统工作状态」。三处有一处对不上就是 bug，不要只看一处就算过。

---

## A. 单机（主服务器自己计时）

| # | 操作 | 期望 |
|---|------|------|
| A1 | 选项目 → 就位 → 发令 → 跑完一组 | 面板/大屏成绩同步出现；名次正确 |
| A2 | 赛前把某道标 **TRI**，然后正常比这一组 | **那道照常计时出成绩**（触板/盲表/分段都有），备注栏红色 TRI，不进名次；其余人名次不因他改变 |
| A3 | 某道判 **DSQ / DNS / DNF** | 面板备注栏立刻显示；大屏同步；该道不占名次 |
| A4 | 点「确认本组成绩」 | 赛程树标 [已完赛]；大屏自动切组成绩 |
| A5 | 确认后再点判罚按钮 | **应被拒绝**并弹窗说明"已完赛不许改" |
| A6 | 点「解锁本组成绩」（二次确认 + 手输组号 + 填原因） | 赛程树 [已完赛] 消失；系统日志和竞赛库审计表各一条 |
| A7 | 解锁后重新判 DNS/DSQ/TRI | **面板备注栏立刻变**（这里栽过：以前面板攥着旧对象，数据改了界面不动） |
| A8 | 改完再点「确认本组成绩」 | 重新锁上；备注栏的判罚**不能消失**（这里栽过：状态存两处只回填了一份） |
| A9 | 等 15 秒以上再看备注栏 | 仍在（10 秒一次的库回读会刷内存，回读必须把两份状态都填回去） |

## B. 计时端（RemoteTimingControl）+ 主服务器

| # | 操作 | 期望 |

| B1 | RTC 上选项目、比一组 | **主服务器「系统工作状态」的"当前比赛"跟着显示**，带"（计时端）"字样 |
| B2 | 重跑 A2~A9 全部 | 与单机表现一致；额外确认主服务器那边的成绩、名次、判罚状态都对 |
| B3 | RTC 上按大屏相关按键（比赛视图/组成绩/总排名/欢迎屏） | 大屏**立刻**切换，不应有明显延迟（这条走的是大屏专用包，不是整包） |
| B4 | 成绩发布 → 再按「比赛视图」 | **大屏回到比赛视图**（这里栽过：确认后的自动跳转压过了手动切换） |

## 三种反复出问题的形状（改代码时对照）

1. **同一份数据存两处** —— `sw.Status` / `r.Status`；`sw.CurrentRank` / `r.Rank`；
   `sw.Heat·Lane` / `StageAssignment`。
   **规矩：写入口就把两份对齐**，不要让下游十几处各自判断该信哪份；
   读的时候用 `GetEffectiveStatus(sw, r)` 这类统一取值函数。

2. **缓存字段只在部分路径更新** —— 典型是 `_scoringControlMode`：只在"有客户端连上
   本机"时更新，而 RTC 的客户端连的是主服务器，于是它一直是初值。
   **规矩：跨机发送的字段一律发送时现算**，别发缓存值。

3. **界面攥着实体对象引用** —— `LaneRowUI.Swimmer`。收到整包时 `_swimmers` 会整批
   换成新对象（集合实例不变，所以表格绑定没事，但单个引用全成孤儿）。
   **规矩：界面每次刷新按主键（道次/号码）重新认一遍人**，别跨帧存对象引用。
