# 大屏推送瘦身 —— 视图字段核对表

2026-08-25 核对，**改代码前必看**。

## 目标（用户定的）

```
开机          取一次静态数据，大屏自己存住
比赛中        只推当前组那几行
下显示命令    命令自带这一个视图的数据，其余不发
大屏          收到就显示，一直显示到下一条命令来 —— 不需要每 100ms 喂一次
```

## 现状：所有视图切换都发整包

`MainWindow.xaml.cs` → `BroadcastDisplayMode(string mode)`：

```csharp
var msg = new { type = mode, data = GetStatusData(), modeExplicit = true };
                              ↑ 整包 278KB，不管切的是哪个视图
```

`SHOW_START_LIST` / `SHOW_HEAT_RESULT` / `SHOW_EVENT_RANKING` /
`SHOW_TEAM_STANDINGS` / `SHOW_RECORDS` / `SHOW_REFEREES` / `SHOW_AWARDS`
**没有一条自带数据**，全靠"把整包再发一遍"让大屏自己挑。

## 顺序不能反

先瘦心跳，这七个视图会**同时变空**，而且只有操作员真去切时才发现 ——
就是 2026-08-25 那次 MR 记录行消失的翻版，范围大七倍。

**必须先让每条命令自带数据，再瘦心跳。**

## 各视图真正读的字段（从 display.html 逐个函数核出来）

| 命令 | 渲染函数 | 读的字段 |
|---|---|---|
| `SHOW_START_LIST` | `renderStartList` | `swimmers` + `currentAgeGroup` `currentEvent` `currentGender` `currentHeat` `currentStage` |
| `SHOW_HEAT_RESULT` | `renderHeatResult` | 同上 + `applicableRecords` |
| `SHOW_EVENT_RANKING` | `renderEventRanking` | `eventRanking` `eventRankingSplit` `rankingRanking` `rankingSelection` |
| `SHOW_TEAM_STANDINGS` | `renderTeamStandings` | **只有** `teamScores` |
| `SHOW_RECORDS` | `renderRecords` | **只有** `records` |
| `SHOW_REFEREES` | `renderReferees` | **只有** `refereeList` |
| `SHOW_AWARDS` | `renderAwards` | `awardRanking` `awardSelection` `eventRanking` + `currentAgeGroup` `currentEvent` `currentGender` |

### 两条关键结论

1. **`swimmers` 是当前组，不是全部。** 出发表、组成绩、比赛视图要的都只是当前组
   那几行 —— 正好就是"只推当前比赛组"。
2. **`allSwimmers`（592 人，260KB，占整包 82%）—— 七个视图没有一个读它。**
   它纯粹是被顺带发出去的。

## 改的时候必须注意

- **公共标量**（`competitionName` 等页头用的）每个视图都得带上 ——
  `_scheduleRender` 里是 `data = _pendingData` **整个替换**，
  只发一个字段会把页头也冲掉。
- **字段名照抄上表**，大屏一个字不用改，显示内容也不会变
  （用户已明确：显示格式和内容定型，不许动）。

## 自检办法

1. 改前先跑一遍，把七个视图逐个切过去截图存档
2. 改后再跑一遍，逐个对比 —— **内容必须一模一样**
3. 跑 `MeetSimulator --baseline` 字段卡口
   （注意：卡口目前有误报，它只比"抓到的最大一帧"，**先修它**）
