# MeetSimulator —— 模拟比赛自动化测试

不碰主程序一行代码，从**外面**把一场比赛完整跑一遍：一头假装计时硬件发帧，
一头假装遥控台走流程，跑完自动核对成绩、分段、名次，并全程采主程序的内存曲线。

```
MeetSimulator ──TCP :5000──▶ 主程序（当它是计时硬件，发 12 字节帧）
              ──WS  :3002──▶ 主程序（当它是遥控台，发比赛控制命令）
                     ▲
                     └── 跑完读 Database\*.json 和 *.db 核对
```

## 用法

```
MeetSimulator.exe [选项]

  --heats N       跑几个组（默认 3，按赛程顺序取前 N 个）
  --lanes N       几条泳道（默认 8）
  --lap-gap S     每段间隔秒数（默认 2.5）
  --host H        主程序地址（默认 127.0.0.1）
  --port N        计时端口（默认 5000）
  --ws N          WebSocket 端口（默认 3002）
  --pause N       各步之间的等待毫秒（默认 300）
  --no-launch     不自动启动主程序（用已经开着的那个）
  --dsq           第 2 组判一个 DSQ
  --dns           第 1 组留一道不来（DNS）
```

退出码 0 = 全部通过，1 = 有失败项。

## 跑之前要准备什么

在主程序目录（`SwimmingScoreboard\bin\x64\Release`）里放好三样：

1. **`Database\<赛事名>.json`** —— 一份真实赛事档案
2. **`last_competition.txt`** —— 内容就是赛事名（UTF-8 无 BOM），主程序启动时按它加载
3. **`timing_connection.json`** —— 让主程序连到模拟器：
   ```json
   { "LastType": "tcp", "TcpHost": "127.0.0.1", "TcpPort": 5000,
     "AutoReconnectOnStartup": true }
   ```

登录窗用 UIAutomation 点掉，需要 `remember.json` 预填用户名密码
（用 `AuthHelper.SaveRemembered` 生成，或手写 DPAPI 加密的那两个字段）。
**没有在主程序里开免登录后门** —— 为跑测试留的口子迟早会留在正式版里。

## 三个踩过的坑（改模拟器之前先看这里）

这三条都是"程序没错、模拟器不真实"，浪费了不少时间：

**1. 触板不是一直开着的。**
发令后到达端触板要等「泳道开关时间」倒计时到点才打开，没开的时候触板帧会被
记进原始计时日志但**不算成绩**。一口气把整场帧灌完，程序一条成绩都不会收。
模拟器的办法是：连上后用 `SET_LANE_CLOSE_SETTINGS` 把开关时间调小（这是程序
本来就有的用户设置），再按 `--lap-gap` 的节奏发。

**2. 帧里的时间和发送节奏无关。**
程序拿帧里报的时间当成绩，墙钟只用来判断触板该不该开着。所以可以报真实成绩
（28 秒一个 50 米）而只用 2 秒发一段，不必真等两分钟。

**3. 到达端要从终点倒推，不能从出发端正推。**
终点端固定（默认左端），最后一段必定到终点端；奇数圈的项目（50/150 米）发令端
和终点端相反，**第 1 段就到终点端**。协议里 `D4 < 10` = 物理左端，`D4 >= 10` =
物理右端（实际道次 = D4-10）。发错端程序会按"当前段应在另一侧完成"直接拒收，
圈数不推进，后面所有段跟着全卡住。
按"从左端出发、第 1 段到右端"正推，200 米（偶数圈）能蒙对，50 米（奇数圈）全错。

## 内存回归

这是 2026-08 那次「400 米比赛内存突然涨几 GB」的回归验证。模拟器全程采
`PrivateMemorySize64`，跑完给曲线和净增，净增超过 500 MB 判失败。

看的时候注意：**内存是跟触板事件数走的，不是跟组数走的**。8 次事件的 50 米组
几乎不涨，32 次事件的 200 米组会涨几十 MB。要判断是不是又回到老路上，
对比同样事件数下的涨幅，别拿组数比。
