# TimingSimulator —— 模拟游泳计时器（带界面）

模拟真实的池边计时硬件，用来调试比赛控制程序，不用进场馆、不用接真设备。

## 跟 MeetSimulator 的区别

| | MeetSimulator | TimingSimulator（本工具） |
|---|---|---|
| 形态 | 命令行，自动跑完整场比赛 | **图形界面，手动按按钮** |
| 连接 | 只能 TCP 客户端 | **TCP 服务端 / TCP 客户端 / UDP 三选一** |
| 用途 | 批量回归、压力测试 | 手工验证单个动作、演示、排查现场问题 |

两者的**帧编码逐字节相同**，MeetSimulator 已经跟主程序跑通过 94 组比赛。

## 用法

```
bin\Release\TimingSimulator.exe
```

也可以用命令行直接指定连接方式（现场部署写进快捷方式，省得每次点对话框）：

```
TimingSimulator.exe --mode tcpserver|tcpclient|udp --host 192.168.1.20 --port 5000
```

界面：

```
盲表3 盲表2 盲表1 出发台 触板 ▏≈≈  触板成绩   (道号)   触板成绩  ≈≈▕ 触板 出发台 盲表1 盲表2 盲表3
      盲表成绩      出发成绩                                        出发成绩      盲表成绩
```

- 触板贴着池壁，左右**镜像对称**，跟实际位置一致
- **触板成绩**放在水面上、紧挨池壁，字大（主角）；出发/盲表成绩字小（参考值）
- 三个成绩栏都**右对齐**；触板成绩显示 `时:分:秒.百分秒`，**前导 0 消隐**
  （`5.36` / `1:09.31` / `1:02:03.45`），跟计时大屏的读法一致
- 发令点：`发令`（快捷键**空格**）开始计时 + 闪光灯 + 喇叭；`复位`（快捷键 **R**）清零并清空所有成绩栏
- 右上角滚动时间；下面一行是收发帧计数
- 界面按屏幕自动缩放，10 道一屏显示完，不滚动

## 连接设置

顶栏【连接设置】→ 对话框里改方式、地址、端口，按【连接】**当场生效**，不用关窗口。

| 方式 | 含义 | 地址栏 |
|---|---|---|
| TCP 服务端 | 本机监听，等比赛控制计算机连过来（**默认**） | 不用填 |
| TCP 客户端 | 本机主动去连对方，连不上每 2 秒重试 | 要填 |
| UDP | 本机在端口上收，同时往对方地址发 | 要填 |

TCP 服务端方式要**先开模拟器再开比赛控制程序** —— 对方启动时只连一次，不重试。

**UDP 用同一个端口收和发**（本机听 `port`，往 `对方:port` 发）。这是计时设备常见做法，
但也意味着在同一台机器上回环测试时会自己收自己。真实部署是两台机器，没这个问题。
若实际设备收发端口不同，需要再加一个"对方端口"字段。

## 通讯协议（12 字节一帧）

```
D0   0xF1  SOH
D1   0x53  'S'
D2   命令码
D3   命令码1
D4   泳道:  <10 = 物理左端(道次即此值)   >=10 = 物理右端(道次 = D4 - 10)
D5   分
D6   秒
D7   百分秒
D8   (时 << 4) | 毫秒首位
D9   保留
D10  标志
D11  0xF4  EOT
```

命令码：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| `0x16` | 触板 | `0x1A` | 出发台 |
| `0x17` | 盲表1 | `0x1C` | 发令 |
| `0x18` | 盲表2 | `0x20` | 复位 |
| `0x19` | 盲表3 | `0x7F` | 滚动时间（每 100ms 一帧） |

## 已验证 / 未验证

**已验证**（2026-08-26，自动化实测）：

- 帧长 12 字节，58 帧余数 0；帧头 `F1 53`、帧尾 `F4` 全部合格
- D4 左右端编码：0 道左=`00` / 右=`0A`，3 道左=`03` / 右=`0D`
- 各命令码与按钮对应正确，时间值与秒表吻合；滚动时间帧约 100ms 一帧
- 帧编码与 MeetSimulator 逐字节一致
- **三种连接方式**：TCP 服务端（收 13 帧，首帧 `0x1C`）、TCP 客户端（主动连上，收 13 帧）、
  UDP（自发自收 25/25 帧）
- 高 DPI（150% 缩放）下窗口完全在工作区内，全部文字不截断

**未验证**：

- **没有接过真实计时硬件**
- 没有跟主程序做过端到端联调（只用假客户端/假服务端收帧核对）
- 主程序侧需要把计时硬件地址指到模拟器的 IP + 端口

## 坑（改代码前先看）

界面：

- **`Dock=Fill` 的行区必须 `BringToFront()`**，否则它抢走整个客户区，顶栏被压成一条缝
- **必须设 `ClientSize` 而不是 `Width`/`Height`**，后者含标题栏边框，会算出比屏幕高一截的窗口
- **必须 `SetProcessDPIAware()`**（`Program.cs`），否则在高缩放屏上整窗被位图拉伸，字发虚、按钮文字被截断
- **必须 `AutoScaleMode = None`**，否则 WinForms 自带的字体 DPI 缩放会跟本程序的 `_s` 缩放打架
- **字号要按 DPI 反向折算**（`F()`/`FM()` 里的 `_dpiAdj`）。字号是磅值，渲染时还会再乘一遍
  系统 DPI，而布局坐标是像素 —— 不折算的话换台高 DPI 的机器字就撑爆版面
- **标签高度一律按 `字体.Height` 算，不许写死**，否则换字号/换 DPI 就切掉下半截
- **`CenterScreen` 在高 DPI 下不可靠**（实测跑到 134,128，右边和第 9 道被推出屏幕），
  自己在 `Load` 里算居中，且左上角不许为负
- **ComboBox 改成 `OwnerDrawFixed` 自绘后，高度由 `ItemHeight` 说了算**（默认 13，
  不显式设会缩成一条缝）。`DropDownList` 不认 `TextAlign`，想右对齐只能自绘
- **对话框（`ConnDialog`）也要自己折算 DPI** —— 主程序 DPI 感知后，对话框拿到的是真实像素

网络：

- 切换连接方式时用 `_netGen` 代数计数器：每次重开 +1，旧收发线程发现代数变了就自己退出，
  避免旧线程还在往已关闭的 socket 上读写

改这个工程的工具链：

- 源码是 UTF-8，用 perl `:raw` 改。**`die` 一定要放在写盘之后** ——
  放前面的话只要有一处没匹配上，前面成功的全部回滚，而且屏幕上还满是 OK，极易误判
- 截图核对界面时，**截图进程也要 `SetProcessDPIAware()`**，否则只截到屏幕左上角一块，
  会误以为窗口超出了屏幕
