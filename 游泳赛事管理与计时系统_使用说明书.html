第一部分 装机与开赛

1. 系统组成

这套系统是一套程序、多个角色：同一份主程序按启动角色表现为不同的机器。

1.1 五个桌面程序

程序 装在哪台 干什么
SwimmingScoreboard.exe 主服务器 竞赛办公室 竞赛数据的唯一权威：名单、赛程、分组、成绩、纪录、文档输出。开 WebSocket(3002) 和网页服务(8080)
RemoteTimingControl.exe 比赛控制（计时端） 池边，接硬件计时器 就位 / 发令 / 计时 / 判罚 / 确认成绩。它才是接着硬件的那台
ScheduleEditor.exe 编排端 编排席 报名、分组、晋级、成绩查改、文档打印。不接硬件、不计时
RegistrationTool.exe 注册工具 检录处 现场补报名
RemoteDisplayControl.exe 显控 大屏机位 大屏预览与切换

1.2 六个网页端

浏览器打开 http://<主服务器IP>:8080/xxx.html：

页面 给谁用
display.html 大屏：比赛实况、组成绩、总排名、颁奖、欢迎屏、日程
race_control.html 比赛控制网页版（平板可用）
query.html 成绩查询（观众/教练）
register.html 在线报名
checkin.html 检录台
leaderboard.html 排名屏

1.3 三种典型摆法

A. 单机（小型比赛）

主服务器一台包办：数据 + 计时 + 大屏。大屏浏览器连本机 8080。

B. 主服务器 + 计时端（推荐，本说明书默认）

主服务器管数据，计时端在池边管计时，两台各司其职。大屏和其它网页都连主服务器。

C. 主服务器 + 计时端 + 编排端（大型比赛）

再加一台编排席，比赛进行中同时做后面项目的编排。

⚠ B、C 两种摆法下，主服务器启动时要加角色参数（见 2.3），它会自动摘掉「比赛控制」页——计时是计时端的事，摘掉入口免得两头发令。

1.4 机器要求

  • Windows 10 / 11，64 位
  • .NET Framework 4.5 以上（系统自带）
  • VC++ 2015-2022 运行库（安装包自带，装机时自动装）
  • 计时端需要一个串口或网口接硬件计时器
  • 各机在同一局域网，网段互通

2. 安装与启动

2.1 安装

  1. 解压 SwimmingScoreboard_Setup_vYYYYMMDD_N.zip
  2. 右键 Setup.exe → 以管理员身份运行
  3. 选安装目录（默认 C:\SwimmingScoreboard）→ 下一步到底

安装器会做三件事：铺程序文件、装 VC++ 运行库（已装过自动跳过）、建桌面快捷方式。

⚠ VC++ 运行库不能跳过。 缺它 SQLite.Interop.dll 加载不了，竞赛库全程打不开——成绩不入库、没有名次、组成绩生不出来，而界面上看不出任何异常。现场为这个白跑过一整天。现在程序启动时会弹窗告警，但最好还是让安装器装上。

2.2 网页文件必须跟 exe 一起更新

⚠ 网页和主程序是同一个版本一起改的。只换一半会出现"设备状态灯不刷新""比赛日志不动"这种看不出根由的毛病。

系统自己会把关：

  • 网页由主程序提供，一律不进浏览器缓存，刷新就是最新的
  • 页面和主程序各带一个版本号，对不上时页顶挂红条写明两边版本，同时在主服务器「系统日志」里点名

看到红条就按 Ctrl+F5 强制刷新；还不一致说明那台机器的 Web\ 目录没跟着更新。

2.3 启动顺序

① 主服务器（先起）

双击桌面图标即可。如果是"主服务器 + 计时端"的摆法，改用带参数的快捷方式：

SwimmingScoreboard.exe --role server

加了 --role server 之后：

  • 「比赛控制」页被摘掉（不是禁用，是根本进不去）
  • 它不再承担计时，所有计时命令一律回绝并说明原因

启动后看顶栏：服务器地址: ws://192.168.x.x:3002 | Web页面: http://192.168.x.x:8080，把这个 IP 告诉其它机器。

② 计时端

双击 RemoteTimingControl.exe → 登录 → 顶部「主服务器」填主服务器 IP → 连接。

再到「比赛控制 → 系统硬件」连上硬件计时器。

③ 编排端 / 注册工具 / 显控

同样填主服务器 IP 连接。

④ 大屏和网页

浏览器打开 http://<主服务器IP>:8080/display.html，按 F11 全屏。

2.4 登录

五个桌面程序共用一套深色登录窗。首次运行的默认账号在各自的凭据文件里（见附录 B），登录后可在「参数设置 → 用户名和密码」里改。

2.5 防火墙

首次启动 Windows 会问是否允许网络访问，必须选"允许"（专用网络 + 公用网络都勾）。否则别的机器连不上。

需要放行的端口：3002（WebSocket）、8080（网页）。

3. 办一场比赛：完整流程

下面这条线走完，就是一场完整的比赛。每一步括号里是在哪台机器上做。

3.1 赛前（主服务器 / 编排端）

① 新建赛事

「赛事管理与报名 → 赛事概览 → 新建赛事」，填名称、日期、地点、泳池规格（长度 / 道数 / 道次编号起点）、裁判名单。

② 组别 / 项目 / 性别 / 赛次

「比赛参数设置管理」里配好本场用到的组别（含年龄区间）、项目、性别、赛次。这几张表是后面所有下拉框的来源。

③ 报名

三条路任选：

  • 「运动员管理 → 添加」手工录
  • 「运动员管理 → 导入 CSV」批量导（表头见附录 C）
  • 网页 register.html 让各队自己报，检录处用 RegistrationTool.exe 补录

接力队在「接力队管理」里建，四棒队员逐一填。

⚠ 右侧那块「运动员注册」表单只在运动员管理和接力队管理两页出现，其它页会自动收起——不是消失了，是那些页用不上它。

④ 生成日程

「赛程管理 → 一键生成日程」：按报名人数估算组数、排出场次和时间。生成后可在表格里手工调。

⑤ 分组

  • 「项目自动分组」：按报名成绩蛇形分组，遵循 FINA SW 3 规则（见 6.2）
  • 「手动分组」：单项目逐个排
  • 「追加分组」：只给新增的、还没分组的人补位
  • 「导入分组表 (Excel)」：从外部分组表导入

⑥ 打印秩序册

「文档编辑/输出/打印 → 秩序册」。

3.2 检录（检录台）

网页 checkin.html 或桌面端点名。没来的人标 DNS。

⚠ 检录标的 DNS 会一路带进竞赛库和成绩单，不用在计时端重标。

人不够时用「并组 / 取消组」把小组并掉（见 7.3）。

3.3 比赛（计时端）

对每一组重复下面六步：

步 动作 说明
1 赛程导航里点到这一组 中间「泳道实时状态」出现本组名单
2 按准备就绪 出发台打开，大屏切到本组
3 发令 硬件发令或按开始比赛
4 比赛中 触板/盲表自动记录，分段、反应时、圈数实时显示
5 需要判罚就判 DSQ / DNS / DNF / TRI（见 4.3）
6 按确认本组成绩 成绩锁定入库，大屏自动切到本组成绩

然后按计时复位，进入下一组。

3.4 赛后（主服务器 / 编排端）

  • 「成绩与排名」查看名次、团体总分
  • 「晋级处理」按预赛成绩排半决赛/决赛
  • 「文档编辑/输出/打印」出成绩册、破纪录报表、获奖证书
  • 「系统日志与数据 → 备份」把赛事档案存一份

第二部分 规矩

4. 五条规矩

这一章是整个系统行为的根。界面上所有"不让做"的地方，都出自下面五条。

4.1 比赛控制归谁：EXE > 网页 > 主服务器

同一场比赛只能有一处发令。次序定死：

优先级 谁 有更高优先级在场时
1（最高） 比赛控制程序（RemoteTimingControl.exe） 永不被锁——它接着硬件
2 比赛控制网页（race_control.html） 计时按钮停用，顶部挂橙条说明
3（最低） 主服务器的「比赛控制」页 页签变灰、点不进去

被挡下的不只是按钮：服务端会硬拦。就位、发令、复位、确认成绩、判罚、跳圈、手输成绩，以及硬件连接/断开、设备全开，凡是从低优先级那头发来的一律回绝并说明原因——灰按钮防不住旧版页面和浏览器缓存，而两处同时发令，谁也说不清现在是什么状态。

切项目、切组次、显示控制不受影响，网页照常能用——它们管的是数据和大屏，不是发令。

高优先级那头一退出，低的自动恢复，不用重启。

4.2 已完赛的组不许改

"已完赛" = 操作员点过「确认本组成绩」、赛程树上标了 [已完赛]。 不是"看着比完了"，也不是"全员都有成绩"。

一旦已完赛：

想做的事 结果
改成绩、判 DSQ/DNS/DNF/TRI、撤销标记 拒绝，弹窗说明
并组、取消组 拒绝
交换泳道、上移下移、加人、移出 拒绝
整项重排（手动/追加/自动分组、导入分组表） 整项拒绝
从文件导入成绩覆盖这一组 跳过，并在完成弹窗里列出跳过了哪几组

唯一的出路是「解锁本组成绩」（见 4.4）。

4.3 TRI 是试游，要计时，不排名

计时 出成绩 排名 计分 算纪录
正常 ✅ ✅ ✅ ✅ ✅
TRI 试游 ✅ ✅ ❌ ❌ ❌
DSQ / DNS / DNF — ❌ ❌ ❌ ❌

赛前就把某道标成 TRI，那道照常计时——触板、盲表、分段、反应时全都正常记录，成绩照常显示，备注栏红色 "TRI"，只是不进名次、不占名次、不参与团体计分、破纪录也不算他。

空道也可以临时标 TRI（会自动建一个占位运动员），用于测试触板。

4.4 解锁本组成绩

「确认本组成绩」一按，这一组就锁死了。可现场常有的事是——按错了，或者按下去之后才发现某道成绩不对。没有解锁，那条错成绩就永远钉在那儿。

所以留了这个口子，在「比赛控制」页确认键正下方，琥珀色的「解锁本组成绩」。

用法：

  1. 正在计时/已就位时不给解（这一组还没比完）
  2. 第一道确认：弹窗写清是哪一组、解开之后会怎样
  3. 第二道确认：手输组号 + 必填原因——手输组号是防手滑的，看一眼弹窗就点"是"的人输不出那个数
  4. 解开后这一组回到"有成绩但没确认"：成绩能改、判罚能改
  5. 改完必须再点一次「确认本组成绩」重新锁上

留痕：系统日志一条，竞赛库审计表一条，记谁、几点、为什么。日志会滚掉，审计表不会。

⚠ 解锁只在计时端做（主服务器角色没有「比赛控制」页）。确认是在哪台按的，就在哪台解。

4.5 比赛中可以改别的项目

比赛进行中，编排端照样可以对别的项目、别的组做并组、调道次、晋级分组——只有正在比的那一组锁着。

这靠两件事做到：

① 按组上锁，不是按"比赛中"一刀切。

判"这一组动不得"只有这些情形：它就是正在计时/已就位的那一组；它已完赛；它成绩已录但还没确认；计时端正开着它。其余一律放行。

② 改动走增量补丁，不推整包。

编排端的改动只把"这一次操作"发给主服务器（并组就发并组，改分组就发那一项的分组表），主服务器照着改那几个人——不重载整库、不换对象，正在计时的那一组一个字节都不碰。

被拒时编排端会明确告诉你原因，并把数据重新取一遍，不会出现"以为存上了其实没有"。

5. 数据存在哪，怎么不丢

5.1 三层存储

层 是什么 什么时候写
内存 界面上看到的一切 随时
当前组存储 本组那十来行：current_heat.db + current_heat_progress.json（几 KB） 比赛中每个计时事件
竞赛库 + 赛事档案 meet.db + Database\<赛事名>.json 点「确认本组成绩」那一下

⚠ 比赛过程中不写主库、不写整包。 中间过程只往"当前组"那一份里写。这是 400 米那次内存涨到几 GB 之后定下的规矩——那次的根因就是每次触板都把整个 1.2MB 的赛事包序列化一遍。

5.2 崩了怎么办

比赛中途程序被强杀或断电：重开程序、加载同一赛事，会弹窗"发现上次没走完的一组，已把进度捡回来"，成绩从当前组进度小文件恢复。核对无误后再点「确认本组成绩」。

已确认过的组不受影响——它们早就进库了。

5.3 名次以库为准

一组确认之后，这组的名次只有竞赛库里那一份。界面、大屏、打印读的都是它，谁都不再自己算。所以偶尔会看到"确认后名次微调"——那是库里重排的结果，是对的。

6. 分组规则

6.1 组次号与空号

并组 / 取消组之后，组次号保留空号。第 2 组并进第 1 组，它仍然占着 2 号并标记"已取消"，总组数不减。

秩序册已经印到运动员手上了，把原第 3 组改叫第 2 组，现场会大乱。

赛程树、大屏、上一组/下一组都会跳过被取消的组。

6.2 自动分组（FINA SW 3）

按 World Aquatics SW 3.1.1.4 / 3.1.1.5 / 3.1.2 标准实现：

短距离项目（50 / 100 / 200 米）

  • seedHeats = min(总组数, 3)：最后 3 组进行循环（种子）排位
  • 前面组进行直接排位，由慢到快编号；最慢组（第 1 组）拿剩余不满人数
  • 种子分配：第 1 名 → 最后组中道，第 2 名 → 倒数第 2 组中道，第 3 名 → 倒数第 3 组中道；第 4 名 → 最后组次中道（lanePriority[1]），依次循环填满

中长距离 / 接力（400 / 800 / 1500 米 / 4×N 接力）

  • seedHeats = min(总组数, 2)：最后 2 组进行循环（种子）排位
  • 前面组直接排位
实现位置：HeatScheduler.AssignFinaSeeding(...)，按 IsShortDistanceEvent(eventName) 自动判定距离类别。

矛头泳道（Spearhead）分配

泳池 优先级（最快→最慢）
8 道 4, 5, 3, 6, 2, 7, 1, 8
10 道 4, 5, 3, 6, 2, 7, 1, 8, 0, 9

成绩最快者必占 4 道；最慢者排到边道（10 道场景下 0/9 道）。

6.3 道次分配

新人填空道，靠中间优先（4-5-3-6-2-7-1-8 这种顺序）。目标组原有的人道次不动。之后可用「上移 / 下移 / 交换泳道」人工调。

第三部分 各界面详解

7. 主服务器

7.1 系统工作状态

开机第一眼看这页。

当前比赛：项目 / 赛次 / 组次 / 状态 / 竞赛模式 / 泳池规格。

⚠ 计时端在跑时，这里显示的是计时端那一组，后面带"（计时端）"字样。计时端一退出就清空——正常退出立刻清，硬断电最多 30 秒后清。

连接状态：大屏、排名屏、报名端、计时 EXE、计时 Web 各连了几个，硬件计时器状态。红色 0 = 没连上。

顶栏：服务器地址、内存占用（带「释放」按钮）、电池电压、硬件计时器、控制模式（本地 / 远程EXE / 远程Web）。

7.2 赛事管理与报名

七个子页：赛事概览、运动员管理、接力队管理、赛程管理、出场编排微调、比赛参数设置管理、记录管理。

右侧「运动员注册」表单只在运动员管理 / 接力队管理两页出现，其余页自动收起并把宽度让给左边表格。

出场编排微调

选定 组别/性别/项目/赛次/组 之后：

按钮 作用
上移 / 下移 同组内换道次顺序
交换泳道 与另一人换，或移到空道
增加到本组 把未分组的人放进来
移出本组 把人从这个赛次的分组里拿掉
临时加人 现场补一个人/一支接力队（默认未分组）

并组 / 取消组

检录后发现某组人不够（比如第 2 组只来 2 人），把它整组并进第 1 组。

  • 对话框里每组标着人数；动不得的组标 "(锁定)" 并写明原因
  • 选源组 → 选目标组（或"仅取消，不并入"）→ 填原因 → 执行
  • 组次号保留空号，源组标记已取消
  • 并过来的人按报名成绩由快到慢填空道
  • 只能在没有成绩之前并

7.3 记录管理

维护世界/亚洲/全国/省/市/赛会等各级纪录。

按钮 作用
添加纪录 加一行空白，填好之后要点「保存纪录」

8.3 计时复位的两种含义

A) 本组已确认成绩 → 彻底复位，自动跳到下一组准备开赛。已确认的成绩永久锁定，不受影响。

B) 本组未确认（抢跳召回重赛）→ 清掉本组的时间和分段，保留备注（DSQ/DNS/DNF/TRI），停在当前组。要清备注只能用「取消备注」。

8.4 判罚

  • DSQ：接力项目会先问犯规棒次，保留前面几棒的分段
  • DNS / DNF：该道不再接收数据
  • TRI：照常计时，只是不排名（见 4.3）
  • 取消备注：撤销判罚，成绩恢复

⚠ 判罚会同时写进内存和当前组存储；确认成绩时一并入库。已完赛的组不许判罚——要改先解锁。

8.5 备用成绩（争议时用）

每道的触板时间、出发台反应时、盲表 1/2/3、手动触板左右，全部保留。有争议时在「查询原始数据」里逐条比对。

9. 编排端（ScheduleEditor）

不接硬件、不计时，只管竞赛数据。适合比赛进行中同时做后面项目的编排。

能做：报名增删改、分组编排、并组、晋级处理、成绩查改、纪录维护、文档打印。

同步方式：

  • 并组、分组调整、晋级、纪录 → 增量补丁，秒级到主服务器，比赛中也能做
  • 其它改动 → 整包保存；比赛中主服务器正在计时时会拒绝，弹窗告诉你等计时复位或确认成绩后再存

被拒时：本机数据会从主服务器重新取一次，你刚才的改动会被撤销——所以看到拒绝提示就要重做一遍，不要以为存上了。

附录 A：硬件通讯协议

A.1 帧格式

F1 53 [CMD] [D3] [D4] [D5] [D6] [D7] [D8] [D9] [D10] F4
 │  │   │    └───────────── 8 字节数据 ─────────────┘    │
 │  │  命令码                                          帧尾
 SOH 'S'

共 12 字节，D0=0xF1（SOH），D1=0x53（'S'），D2=命令，D11=0xF4（EOT）。

A.3 关键命令详解

0x43 Set_MatchEvent（比赛准备）

  • D3 总圈数 / D4 右触板次数 / D5 左触板次数
  • D6 道次位图 0–4（bit=1 即占用 / 开启）
  • D7 道次位图 5–9
  • D8 接力标志（1=接力 / 0=个人）
  • lane 索引按"屏幕位置"编码：逆序模式下 hwIndex = 9 − lane
  • 在"准备就绪"按下时发送，紧接 30–50 ms 延迟后再发 0x21 Ready

0x60 Set_LaneEnableDisable

  • D3 泳道号 0–9（必须单道，不支持 0xFF）
  • D4 1=启用 / 0=屏蔽（同时切换硬件道次按钮显示）

与 0x47 / 0x4C 三命令的语义区分：

命令 作用范围 效果
0x47 全部或单道 整体启用 / 禁用 TP/SB/MB（不动道次按钮显示）
0x60 仅单道 同时切换 TP/SB/MB 启用 + 道次按钮显示状态
0x4C 全部或单道 设备状态机覆盖（接受所有信号 vs 按状态过滤）

0x61 Set_LapRemaining

  • D3 泳道号 0–9
  • D4 端：0=左 / 1=右
  • D5 剩余圈数 0–255

PC 端"剩余圈数 ▲▼" spinner 调整后立即下发，硬件 laps[D3][D4] = D5 并重画对应道的圈数显示。

0x62 / 0x63 双向同步

  • 0x62 Set_LaneOrder：D3=0 正序 / 1 逆序
  • 0x63 Set_FinishPosition：D3=0 终点左端 / 1 终点右端

PC 改设置时下发硬件；硬件 net_test 子界面用户改后回主控时上报，PC 自动更新 _laneCloseSettings + ApplyTouchpadInstallModeToLanes() 刷新各道 NotInstalled + Broadcast() 推全客户端。双向命令均禁止回发以防回环。

0x64 Set_TimingsBundle（硬件 → PC）

硬件 net_test 子界面"参数设置"输入完 5 项时间编辑框后退出，把当前值一帧打包上报：

字段 含义 单位
D3 泳道封闭时间 LaneCloseTime 秒
D4 触板延迟关闭 ResultConfirmCloseDelay 秒
D5 出发台延迟关闭 StartBlockCloseDelay 秒
D6 盲表代替成绩延迟 BlindReplaceDelay 秒（整数）
D7 成绩显示时间 SplitDisplayTime 秒
⚠ BlindReplaceDelay 单位 v2026.05.18 起统一为"整数秒"；旧命令 0x41 D5 / 0x42 子码 0x09 是 0.1 秒精度，PC 端 SendXxx 时会乘 10 转换。硬件内部 MBdelay_Time = d5 * 10。

0x65 Set_RefreshDisplay

PC 参数对话框 OK 后下发，硬件主控按新参数主动重画一屏，但不丢失比赛状态（缺道 / 剩余圈数 / TP/SB/MB Open_State 全部保留再恢复）。D3–D10 全 0。

0x4B BatteryVoltage（硬件 → PC）

D3:D4 大端 mV，主控 = (D3<<8 | D4) / 1000.0 V。

区间 颜色
≥ 7.4 V 绿
6.8 ~ 7.4 V 黄
< 6.8 V 红

接收后实时刷新主服务器"系统硬件"栏 + 远程台顶栏。30 秒无更新自动置 "—"。

0x39 Set_DateTime（周期校时）

连接硬件后立即下发一次；之后 DispatcherTimer _clockSyncTimer 每 30 分钟刷一次。字段 D3 YearLo / D4 YearHi / D5 Month / D6 Day / D7 Hour / D8 Min / D9 Sec。

A.4 帧间延迟

TimingBridge.DelayBetweenFrames(int ms = 50) 用于连续下发时的等待。硬件状态机串行处理，相邻帧间隔不足会丢帧：

场景 延迟
0x43 之后 → 0x21 Ready 20 ms
0x40 之后 → 0x42 子码序列（共 ~9 帧） 50 ms × N
每道设备状态帧（最多 10 道） 30 ms × N
0x20 复位后 → 任何后续帧 50 ms

按下"M.发令"的总下发时延约 ~800 ms，业务可接受。

A.5 远程 EXE 转发（_REPORT 子命令族）

RemoteTimingControl.exe 直连硬件时，把硬件→PC 的扩展命令拆为 WebSocket TIMING_CMD 子命令转发给主服务器：

硬件帧 WebSocket TIMING_CMD data 字段
0x4B BatteryVoltage BATTERY_REPORT { voltage }
0x64 TimingsBundle TIMINGS_BUNDLE_REPORT { laneCloseTime, ... } 共 5 项
0x62 LaneOrder LANE_ORDER_REPORT `{ order: "forward" "reverse" }`
0x63 FinishPosition FINISH_POS_REPORT `{ pos: "left" "right" }`
0x3A PoolSingleOrDouble POOL_SIDE_REPORT { single: bool }
0x47 LaneOpenClose LANE_OPEN_CLOSE_REPORT `{ lane: -1 0..9, open: bool }`

主服务器侧 HandleHardwareReportForwarded 还原为 TimingData 后调 ProcessTimingDataFromHardware 复用原处理路径。

仅适用于"EXE 直连硬件"模式；主服务器直连硬件时走 OnTimingData 原路径。

附录 D：本版主要变更（v2026.05.26 → v2026.09.14）

比赛中可以改别的项目

  • 并组、分组调整、晋级处理、纪录维护全部改走增量补丁，比赛中也能做，只有正在比的那一组锁着
  • 比赛中不再有任何整包写盘：过程数据只写"当前组"那一份，确认成绩才入库
  • 主服务器不承担计时时，不再用"比赛中"一刀切锁住编排端和查询端

已完赛保护 + 解锁

  • "已完赛"统一定义为点过「确认本组成绩」
  • 已完赛的组：分组、道次、成绩、判罚一律不许改
  • 新增「解锁本组成绩」：二次确认（手输组号 + 必填原因）+ 系统日志 + 竞赛库审计
  • 解锁 → 改 → 再确认，改动会正确写回竞赛库

比赛控制优先级

  • 定死 EXE > 网页 > 主服务器，服务端硬拦，不只是灰按钮
  • 计时端在跑时主服务器「比赛控制」页变灰；退出后自动恢复
  • 主服务器「当前比赛」跟随计时端显示，计时端退出后清空

TRI 规则纠正

  • 赛前标 TRI 的泳道照常计时出成绩，只是不排名、不计分、不算纪录
  • （此前会把该道整场的计时闸门关掉，触板盲表全无数据）

传输与内存

  • 比赛日志改增量追加（一条事件约 70 字节，此前每帧重发最多 640KB 累积文本）
  • 设备状态改变一次推一次，实时性不降反升
  • 整包不再定时重发，改成"数据变了吭一声、客户端要用时才取"
  • 网页一律不进浏览器缓存；页面与主程序版本号比对，不一致挂红条并在日志点名

界面

  • 「运动员注册」表单只在 运动员管理 / 接力队管理 两页出现
  • 记录管理加「保存纪录」按钮（此前就地编辑没有任何保存动作）
  • 大屏：手动按「比赛视图」时不再被"确认后自动跳组成绩"抢走

安装与打包

  • 安装包内置 VC++ 2015-2022 运行库，装机自动安装（打包时会校验微软签名）
  • query.html 补进安装包（此前从未随包分发）
  • 开发机日志、内部笔记不再混进客户包
