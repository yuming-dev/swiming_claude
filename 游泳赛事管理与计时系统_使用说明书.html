第一部分 装机与开赛

1. 系统组成

这套系统是一套程序、多个角色：同一份主程序按启动角色表现为不同的机器。

1.1 五个桌面程序

程序装在哪台干什么
SwimmingScoreboard.exe 主服务器竞赛办公室竞赛数据的唯一权威：名单、赛程、分组、成绩、纪录、文档输出。开 WebSocket(3002) 和网页服务(8080)
RemoteTimingControl.exe 比赛控制（计时端）池边，接硬件计时器就位 / 发令 / 计时 / 判罚 / 确认成绩。它才是接着硬件的那台
ScheduleEditor.exe 编排端编排席报名、分组、晋级、成绩查改、文档打印。不接硬件、不计时
RegistrationTool.exe 注册工具检录处现场补报名
RemoteDisplayControl.exe 显控大屏机位大屏预览与切换

1.2 六个网页端

浏览器打开 http://<主服务器IP>:8080/xxx.html：

页面给谁用
display.html大屏：比赛实况、组成绩、总排名、颁奖、欢迎屏、日程
race_control.html比赛控制网页版（平板可用）
query.html成绩查询（观众/教练）
register.html在线报名
checkin.html检录台
leaderboard.html排名屏

还有一个 control.html（显示控制网页，见 10.4）和一个开发/调试专用的 test_bot.html（自动化测试机器人，不随正式安装包分发，使用说明书里也不详细介绍）。

1.3 三种典型摆法

A. 单机（小型比赛） 主服务器一台包办：数据 + 计时 + 大屏。大屏浏览器连本机 8080。

B. 主服务器 + 计时端（推荐，本说明书默认） 主服务器管数据，计时端在池边管计时，两台各司其职。大屏和其它网页都连主服务器。

C. 主服务器 + 计时端 + 编排端（大型比赛） 再加一台编排席，比赛进行中同时做后面项目的编排。

⚠ B、C 两种摆法下，主服务器启动时要加角色参数（见 2.3），它会自动摘掉「比赛控制」页——计时是计时端的事，摘掉入口免得两头发令。

1.4 机器要求

  • Windows 10 / 11，64 位
  • .NET Framework 4.5 以上（系统自带）
  • VC++ 2015-2022 运行库（安装包自带，装机时自动装）
  • 计时端需要一个串口或网口接硬件计时器
  • 各机在同一局域网，网段互通

2. 安装与启动

2.1 安装

1. 解压 SwimmingScoreboard_Setup_vYYYYMMDD_N.zip 2. 右键 Setup.exe → 以管理员身份运行 3. 选安装目录（默认 C:\SwimmingScoreboard）→ 可以选择是否创建桌面快捷方式（默认勾选）→ 下一步到底

安装器会做三件事：铺程序文件、装 VC++ 运行库（已装过自动跳过）、建桌面快捷方式（除非上一步取消勾选）。

⚠ VC++ 运行库不能跳过。 缺它 SQLite.Interop.dll 加载不了，竞赛库全程打不开——成绩不入库、没有名次、组成绩生不出来，而界面上看不出任何异常。现场为这个白跑过一整天。现在程序启动时会弹窗告警，但最好还是让安装器装上。

2.2 网页文件必须跟 exe 一起更新

⚠ 网页和主程序是同一个版本一起改的。只换一半会出现"设备状态灯不刷新""比赛日志不动"这种看不出根由的毛病。

系统自己会把关：

  • 网页由主程序提供，一律不进浏览器缓存，刷新就是最新的
  • 页面和主程序各带一个版本号，对不上时页顶挂红条写明两边版本，同时在主服务器「系统日志」里点名

看到红条就按 Ctrl+F5 强制刷新；还不一致说明那台机器的 Web\ 目录没跟着更新。

2.3 启动顺序

① 主服务器（先起）

双击桌面图标即可。如果是"主服务器 + 计时端"的摆法，改用带参数的快捷方式：

SwimmingScoreboard.exe --role server

加了 --role server 之后：

  • 「比赛控制」页被摘掉（不是禁用，是根本进不去）
  • 它不再承担计时，所有计时命令一律回绝并说明原因

启动后看顶栏：服务器地址: ws://192.168.x.x:3002 | Web页面: http://192.168.x.x:8080，把这个 IP 告诉其它机器。

② 计时端

双击 RemoteTimingControl.exe → 登录 → 顶部「主服务器」填主服务器 IP → 连接。 再到「比赛控制 → 系统硬件」连上硬件计时器。

③ 编排端 / 注册工具 / 显控

同样填主服务器 IP 连接。

④ 大屏和网页

浏览器打开 http://<主服务器IP>:8080/display.html，按 F11 全屏。

2.4 登录

五个桌面程序共用一套深色登录窗。首次运行的默认账号是 admin / 123456（凭据文件不存在时程序自动写入这一默认值，文件位置见附录 B），登录后请立刻在「参数设置 → 用户名和密码」里改成自己的密码。

2.5 防火墙

首次启动 Windows 会问是否允许网络访问，必须选"允许"（专用网络 + 公用网络都勾）。否则别的机器连不上。

需要放行的端口：3002（WebSocket）、8080（网页）。

2.6 中文/English 双语界面

本版起，全部五个桌面程序和全部网页端都支持中文/English 双语切换，适合有境外运动员/裁判参与的国际性比赛。

在哪切换：

位置怎么切
主服务器 / 计时端 / 编排端 / 注册工具 / 显控（五个桌面程序）「设置」页里的 中文 / English 按钮，点一下整个程序界面（含弹窗、菜单、系统日志、导出文件表头）跟着切
网页端（display.html / race_control.html / query.html / register.html / checkin.html / leaderboard.html / control.html）各自页面右上角独立的语言按钮，存在浏览器本地，不跟桌面端联动

跨客户端自动同步（系统级特性）：主服务器「设置」页切一次语言，所有已连接的桌面客户端（ScheduleEditor.exe / RemoteTimingControl.exe / RegistrationTool.exe / RemoteDisplayControl.exe）会自动跟着切；这几个客户端一连上主服务器，也会立刻把自己的界面语言校准到主服务器当前的语言，不用每台机器分别设置一遍。网页端不受这项同步影响，各自独立选。

还有两处也跟着语言走：

  • 桌面快捷方式和开始菜单的程序名字，切语言后自动改名（中文名 / 英文名对应切换）
  • 计时端切中英文时，会把语言设置同步下发给硬件计时器（协议新命令 0x3B，见附录 A），硬件主控屏上的文字也跟着换

弹窗按钮不依赖 Windows 系统语言：所有确定/取消/是/否弹窗改用程序自绘的样式（AppMessageBox），不再调用 Windows 原生消息框——哪怕操作系统本身是中文 Windows，程序切到 English 后弹窗按钮也会正确显示 OK / Cancel / Yes / No，不会出现"程序是英文，弹窗按钮却还是中文"的错位。

⚠ 项目名、组别名、性别这几项既是显示文字也是内部匹配用的数据值。中英文各有一套标准值（比如性别的 男/女/混合 对应 Men/Women/Mixed），切语言时如果已经报过名，不会把已报名运动员的性别/组别数据跟着强行翻译——所以建议开始报名前先把语言定下来，中途切语言不会丢数据，但下拉框里新旧语言的候选值可能同时出现，容易选错。

3. 办一场比赛：完整流程

下面这条线走完，就是一场完整的比赛。每一步括号里是在哪台机器上做。

3.1 赛前（主服务器 / 编排端）

① 新建赛事 「赛事管理与报名 → 赛事概览 → 新建赛事」，填名称、日期、地点、裁判名单。泳池长度/泳道数量挪到了下一步「比赛参数设置管理」里设置，「赛事概览」上的「比赛模式」现在是只读的，跟着比赛规则走，不在这里单独选。

② 比赛规则 → 一键导入组别 / 项目 / 性别 / 赛次

「比赛参数设置管理」顶部有个「比赛规则」下拉，四个选项：

选项适用场景
国际大赛（FINA / World Aquatics）国际比赛，项目/组别用国际泳联标准英文术语
国内大赛国内常规赛事（原名"国内大赛（中国泳协）"，本版简化为通用名字，不再绑定某一家协会，方便不同国家/地区套用国内规则时使用）
U 系列青少年赛事青少年/校园系列赛事
地区级比赛（省/市/区/校运动会）地区级、单位内部运动会，项目设置更简化

选好之后，系统会自动导入一整套与这条规则匹配的项目表、组别表、性别表、赛次表（长池/短池版本都有，中文/English 版本也都有，跟着当前界面语言自动选对应语种的模板），不用再逐项手工建表。导入后仍可以在各自的编辑窗口里增删改，不是锁死的。

这几张表是后面所有下拉框的来源，务必先确认一遍再开始报名。

③ 报名 三条路任选：

  • 「运动员管理 → 添加」手工录
  • 「运动员管理 → 导入 CSV」批量导（表头见附录 C）
  • 网页 register.html 让各队自己报，或用 RegistrationTool.exe 在检录处补录（见 7.2.3）

接力队在「接力队管理」里建，四棒队员逐一填；本版起接力报名支持一支队报多个接力项目、一次报多支队（见 7.2.3），不再是报一支就锁死。

如果比赛要求号码按单位/性别分段，还可以用「参赛单位及号码分配」（见 7.2.6）统一配置号码规则；不用它系统也会按默认区间自动分号。

⚠ 右侧那块「运动员注册」表单只在运动员管理和接力队管理两页出现，其它页会自动收起——不是消失了，是那些页用不上它。

④ 生成日程 「赛程管理 → 一键生成日程」：按报名人数估算组数、排出场次和时间。生成后可在表格里手工调。

⑤ 分组

  • 「项目自动分组」：按报名成绩蛇形分组，遵循 FINA SW 3 规则（见 6.2）
  • 「手动分组」：单项目逐个排
  • 「追加分组」：只给新增的、还没分组的人补位
  • 「导入分组表 (Excel)」：从外部分组表导入

⑥ 打印秩序册 「文档编辑/输出/打印 → 秩序册」。

3.2 检录（检录台）

网页 checkin.html 或桌面端点名。没来的人标 DNS。

⚠ 检录标的 DNS 会一路带进竞赛库和成绩单，不用在计时端重标。

人不够时用「并组 / 取消组」把小组并掉（见 7.2.5）。

3.3 比赛（计时端）

对每一组重复下面六步：

步动作说明
1赛程导航里点到这一组中间「泳道实时状态」出现本组名单
2按准备就绪出发台打开，大屏切到本组
3发令硬件发令或按开始比赛
4比赛中触板/盲表自动记录，分段、反应时、圈数实时显示
5需要判罚就判DSQ / DNS / DNF / TRI（见 4.3）
6按确认本组成绩成绩锁定入库，大屏自动切到本组成绩

然后按计时复位，进入下一组。

开赛前，务必先看一遍「比赛控制 → ⚙ 参数设置」里的全部参数（见 8.8）——特别是「比赛泳池、设备状态设置」里的终点位置、泳池触板安装方式，装反了整场比赛道次全乱。

3.4 赛后（主服务器 / 编排端）

  • 「成绩与排名」查看名次、团体总分
  • 「晋级处理」按预赛成绩排半决赛/决赛
  • 「文档编辑/输出/打印」出成绩册、破纪录报表、获奖证书
  • 「系统日志与数据 → 备份」把赛事档案存一份

第二部分 规矩

4. 五条规矩

这一章是整个系统行为的根。界面上所有"不让做"的地方，都出自下面五条。

4.1 比赛控制归谁：EXE > 网页 > 主服务器

同一场比赛只能有一处发令。次序定死：

优先级谁有更高优先级在场时
1（最高）比赛控制程序（RemoteTimingControl.exe）永不被锁——它接着硬件
2比赛控制网页（race_control.html）计时按钮停用，顶部挂橙条说明
3（最低）主服务器的「比赛控制」页页签变灰、点不进去

被挡下的不只是按钮：服务端会硬拦。就位、发令、复位、确认成绩、判罚、跳圈、手输成绩，以及硬件连接/断开、设备全开，凡是从低优先级那头发来的一律回绝并说明原因——灰按钮防不住旧版页面和浏览器缓存，而两处同时发令，谁也说不清现在是什么状态。

切项目、切组次、显示控制不受影响，网页照常能用——它们管的是数据和大屏，不是发令。

高优先级那头一退出，低的自动恢复，不用重启。

4.2 已完赛的组不许改

"已完赛" = 操作员点过「确认本组成绩」、赛程树上标了 [已完赛]。 不是"看着比完了"，也不是"全员都有成绩"。

一旦已完赛：

想做的事结果
改成绩、判 DSQ/DNS/DNF/TRI、撤销标记拒绝，弹窗说明
并组、取消组拒绝
交换泳道、上移下移、加人、移出拒绝
整项重排（手动/追加/自动分组、导入分组表）整项拒绝
从文件导入成绩覆盖这一组跳过，并在完成弹窗里列出跳过了哪几组

唯一的出路是「解锁本组成绩」（见 4.4）。

4.3 TRI 是试游，要计时，不排名

计时出成绩排名计分算纪录
正常✅✅✅✅✅
TRI 试游✅✅❌❌❌
DSQ / DNS / DNF—❌❌❌❌

赛前就把某道标成 TRI，那道照常计时——触板、盲表、分段、反应时全都正常记录，成绩照常显示，备注栏红色 "TRI"，只是不进名次、不占名次、不参与团体计分、破纪录也不算他。

空道也可以临时标 TRI（会自动建一个占位运动员），用于测试触板。

4.4 解锁本组成绩

「确认本组成绩」一按，这一组就锁死了。可现场常有的事是——按错了，或者按下去之后才发现某道成绩不对。没有解锁，那条错成绩就永远钉在那儿。

所以留了这个口子，在「比赛控制」页确认键正下方，琥珀色的「解锁本组成绩」。

用法： 1. 正在计时/已就位时不给解（这一组还没比完） 2. 第一道确认：弹窗写清是哪一组、解开之后会怎样 3. 第二道确认：手输组号 + 必填原因——手输组号是防手滑的，看一眼弹窗就点"是"的人输不出那个数 4. 解开后这一组回到"有成绩但没确认"：成绩能改、判罚能改 5. 改完必须再点一次「确认本组成绩」重新锁上

留痕：系统日志一条，竞赛库审计表一条，记谁、几点、为什么。日志会滚掉，审计表不会。

⚠ 解锁只在计时端做（主服务器角色没有「比赛控制」页）。确认是在哪台按的，就在哪台解。

4.5 比赛中可以改别的项目

比赛进行中，编排端照样可以对别的项目、别的组做并组、调道次、晋级分组——只有正在比的那一组锁着。

这靠两件事做到：

① 按组上锁，不是按"比赛中"一刀切。 判"这一组动不得"只有这些情形：它就是正在计时/已就位的那一组；它已完赛；它成绩已录但还没确认；计时端正开着它。其余一律放行。

② 改动走增量补丁，不推整包。 编排端的改动只把"这一次操作"发给主服务器（并组就发并组，改分组就发那一项的分组表），主服务器照着改那几个人——不重载整库、不换对象，正在计时的那一组一个字节都不碰。晋级处理、纪录维护也走这条路。

被拒时编排端会明确告诉你原因，并把数据重新取一遍，不会出现"以为存上了其实没有"。

5. 数据存在哪，怎么不丢

5.1 三层存储

层是什么什么时候写
内存界面上看到的一切随时
当前组存储本组那十来行：current_heat.db + current_heat_progress.json（几 KB）比赛中每个计时事件

⚠ 比赛过程中不写主库、不写整包。 中间过程只往"当前组"那一份里写。这是 400 米那次内存涨到几 GB 之后定下的规矩——那次的根因就是每次触板都把整个 1.2MB 的赛事包序列化一遍。

5.2 崩了怎么办

比赛中途程序被强杀或断电：重开程序、加载同一赛事，会弹窗"发现上次没走完的一组，已把进度捡回来"，成绩从当前组进度小文件恢复。核对无误后再点「确认本组成绩」。

已确认过的组不受影响——它们早就进库了。

5.3 名次以库为准

一组确认之后，这组的名次只有竞赛库里那一份。界面、大屏、打印读的都是它，谁都不再自己算。所以偶尔会看到"确认后名次微调"——那是库里重排的结果，是对的。

6. 分组规则

6.1 组次号与空号

并组 / 取消组之后，组次号保留空号。第 2 组并进第 1 组，它仍然占着 2 号并标记"已取消"，总组数不减。

秩序册已经印到运动员手上了，把原第 3 组改叫第 2 组，现场会大乱。

赛程树、大屏、上一组/下一组都会跳过被取消的组。

6.2 自动分组（FINA SW 3）

按 World Aquatics SW 3.1.1.4 / 3.1.1.5 / 3.1.2 标准实现：

短距离项目（50 / 100 / 200 米）

  • seedHeats = min(总组数, 3)：最后 3 组进行循环（种子）排位
  • 前面组进行直接排位，由慢到快编号；最慢组（第 1 组）拿剩余不满人数
  • 种子分配：第 1 名 → 最后组中道，第 2 名 → 倒数第 2 组中道，第 3 名 → 倒数第 3 组中道；第 4 名 → 最后组次中道（lanePriority[1]），依次循环填满

中长距离 / 接力（400 / 800 / 1500 米 / 4×N 接力）

  • seedHeats = min(总组数, 2)：最后 2 组进行循环（种子）排位
  • 前面组直接排位

实现位置：HeatScheduler.AssignFinaSeeding(...)，按 IsShortDistanceEvent(eventName) 自动判定距离类别。

矛头泳道（Spearhead）分配

泳池优先级（最快→最慢）
8 道4, 5, 3, 6, 2, 7, 1, 8
10 道4, 5, 3, 6, 2, 7, 1, 8, 0, 9

成绩最快者必占 4 道；最慢者排到边道（10 道场景下 0/9 道）。

6.3 道次分配

新人填空道，靠中间优先（4-5-3-6-2-7-1-8 这种顺序）。目标组原有的人道次不动。之后可用「上移 / 下移 / 交换泳道」人工调。

7.2.3 运动员注册——网页版 register.html 和现场工具 RegistrationTool.exe

除了桌面端「运动员管理 / 接力队管理」两页手工录入之外，系统还提供两条专门给"报名"这件事用的通道。它们最终写的是同一张花名册——用哪条路报的名，桌面端「运动员管理」里立刻能看到，不用来回导入导出。

A. 网页 register.html：给各代表队自己报名

在浏览器打开 http://<主服务器IP>:8080/register.html，发给各代表队的教练/领队，让他们在自己的手机或电脑上填。整个页面分两大块：个人项目报名和接力项目报名，操作逻辑完全一致，都是"先攒好一批要报的东西，最后一次性提交"，不是填一条马上交一条：

个人项目报名，从头到尾：

1. 填运动员基本信息：姓名 / 性别 / 出生日期 / 代表队是必填；身份证号这一项本版起改成选填，也不再限制位数和格式——国际比赛的运动员证件号跟国内身份证格式不一样，不再强制要求必须是18位数字，留空或填任意证件号都可以提交 2. 选一个「项目」，填「报名成绩」，点 + 添加项目——这一步只是把这个项目加进页面上的临时列表，还没真正提交 3. 还要给同一个人报别的项目，重复上一步继续加，一个人可以加多个项目 4. 这个人的项目都加完后，可以点 + 添加运动员（或类似的"再报一人"入口）开始填下一个人，如此反复，把整个代表队要报的人都先加进页面的报名队列里 5. 全部人都加完之后，点最下面的 提交全部报名 按钮，才会一次性把队列里所有人的所有项目真正写进主服务器花名册

接力项目报名（本版重点改造，从头到尾）：

⚠ 旧版本这里曾经只能报一支接力队、一个接力项目，报完就锁死了，很多代表队要报多个接力项目（比如男女混合接力 + 男子接力 + 女子接力）或者要报多支队伍时非常不方便。本版起，接力项目报名改成跟上面"个人项目报名"完全一样的两级操作，不再有这个限制：

1. 填这支接力队的信息：队名 / 组别 / 性别 / 项目，再按第 1~4 棒依次填每一棒队员的姓名 / 身份证号（身份证号同样改成选填不限格式） 2. 点 + 添加接力队——这一支队伍、这一个接力项目，先加进页面的临时队列 3. 同一支队伍还要报别的接力项目（比如刚才报了男子4x100接力，还要报混合接力），重新选项目、重新填棒次（队员可以跟上一次一样，也可以不一样），再点一次「+ 添加接力队」——一支队伍可以这样加多个接力项目 4. 要报另一支队伍，同样重复第1步再加，一次报名可以加多支队伍，不限于一支 5. 队列里所有要报的接力队都加完后，点 提交全部接力报名，一次性全部写入主服务器

⚠ 新手容易踩的坑：跟个人项目报名一样，只点了「+ 添加运动员」/「+ 添加接力队」但没点最后那个"提交全部……"按钮，数据都还停留在浏览器页面的临时队列里，刷新页面或关掉浏览器就会丢失，主服务器那边完全收不到。填完一定要点到最后那个绿色的提交按钮。

B. RegistrationTool.exe：现场补报名专用工具

装在检录处的电脑上，专门给赛前赛中"有人漏报了"这种情况现场补录用。启动后先登录（账号密码同其它四个桌面程序，见 2.4），顶部填主服务器 IP 连接。界面分「个人报名」「接力报名」两个标签页，操作方式跟 register.html 完全对齐（本版起同步做了同样的改造）：

7.2.6 参赛单位及号码分配

在「运动员管理」标签左边多了一个标签「参赛单位及号码分配」，专门用来统一管理各参赛单位（代表队/学校/俱乐部）的运动员参赛号码（Bib号）分配方式。这一步不是必须做的——不用它，系统也会按「号码区间设置」（见 7.2.1）给每个人自动分一个号；但如果比赛要求"号码按单位、按性别分段"（比如某代表队的男运动员固定用101~110号），用这个功能能省掉大量手工核对的工作。

从头到尾怎么用：

1. 先选号码分配模式（页面右上角两个单选钮）：

  • 自动分配（平均分布）：系统按单位数量、每单位预留号码数量自动把号码段铺开，适合"不在乎具体号码是多少，只要求不重复、大致连续"的比赛
  • 手工分配（自定义）：每个单位的号码范围自己指定，适合"号码有固定含义"的比赛（比如学校运动会里号码段对应班级）

2. 左边表格「新增单位行」逐个加参赛单位（也可以点「导入单位名称」从已有的参赛单位列表批量带入，不用一个个手打），单位名重复、组别不同视为同一单位报了多个组别，可以分别设置号码段 3. 点选左边某一行单位，右边出现这个单位的详细设置：运动员男子号码段（起止号）、运动员女子号码段（起止号）——两段可以不一样，也可以都留空只填下面的「合并范围」让男女共用同一段连续号码 4. 填完点「应用到本行」，这一个单位的设置才会生效；可以用「上一个 / 下一个」按钮快速切到别的单位继续设置，不用每次都从表格里重新点选 5. 所有单位都设置完，点「预览号码分布」先看一眼有没有重叠、有没有漏配的单位 6. 确认没问题后点「保存设置」，这批号码范围才会真正生效——从这时起，「运动员管理」新增运动员时，选了代表队和性别，系统会自动从对应的号码段里挑下一个可用号

号码优化功能：号码段快用完了，或者想把没分配出去的空号收回来重新利用，点「号码优化功能」会弹出一个小窗口，可以设置"起始号码"和"每个单位保留空号数量"，重新压缩、腾出未使用的号码——用之前务必先把已经报名的运动员数据备份好（系统日志与数据页有备份入口），压缩号码段是不可逆操作，操作前一定要三思。

⚠ 已经有运动员在用某个单位的号码段之后，这个单位的号码范围和分配模式就不能再改了——页面上会用红字提示"该单位/组别已有运动员在使用这个号码段，范围不能再修改"。如果确实需要调整，得先去「运动员管理」把这些运动员的参赛号清空或改掉，才能回来改号码段设置。所以建议在正式开始报名之前，先把号码分配方式定下来、设置好，报名开始之后再改会很麻烦。

设置完还可以在「文档编辑/输出/打印」里打印一份「参赛单位号码分布」报表（表格列：参赛单位 / 组别 / 男子号码分布 / 女子号码分布），方便贴出来给各代表队核对。

8.4 计时复位的两种含义

A) 本组已确认成绩 → 彻底复位，自动跳到下一组准备开赛。已确认的成绩永久锁定，不受影响。

B) 本组未确认（抢跳召回重赛）→ 清掉本组的时间和分段，保留备注（DSQ/DNS/DNF/TRI），停在当前组。要清备注只能用「取消备注」。

8.5 判罚与手工补段

  • DSQ：接力项目会先问犯规棒次，保留前面几棒的分段
  • DNS / DNF：该道不再接收数据
  • TRI：照常计时，只是不排名（见 4.3）
  • 取消备注：撤销判罚，成绩恢复
  • 盲表成绩：手动触板未按、触板故障时，用盲表（手计）时间代替该道成绩。本版确认点下这个按钮后会有明确的成功/失败日志反馈，不再是"按了看不出有没有生效"
  • 手动输入：整道成绩直接手工键入（争议裁决、设备全故障时用）
  • 手工补段：只补某一段/某一圈的分段时间，不动整道最终成绩
  • 道次打开 / 道次关闭 / 全部打开 / 全部关闭：临时启用或屏蔽某道（空道、弃赛道），对应硬件命令 0x60 Set_LaneEnableDisable（见附录 A.3）

⚠ 判罚会同时写进内存和当前组存储；确认成绩时一并入库。已完赛的组不许判罚——要改先解锁（见 4.4）。

9. 编排端（ScheduleEditor：编排记录及成绩处理专用机）

ScheduleEditor.exe 不接硬件、不计时，界面就是主服务器「赛事管理与报名」「成绩与排名」「文档编辑/输出/打印」这几页的独立打包版——7.2、7.4、7.5 三节的截图和操作步骤在编排端上是同一套，唯一区别是编排端要先连上主服务器 IP 才能拿到数据（登录窗和其它四个桌面程序一样，见 2.4）。适合比赛进行中另开一台机器、同时做后面项目的编排，不占用池边计时端。

并组、取消组、分组/道次调整、临场微调（7.2.5）、晋级处理、纪录维护增量补丁（EDITOR_PATCH）：只把这一次操作本身发给主服务器，秒级生效能，只要动的不是正在比/已完赛的那一组（见 4.5）

这一区分是持续加固的部分：早期版本编排端的改动大多走"整包推送"，一次保存等于把整份赛事档案重新推一遍给主服务器，如果那一刻正好有一组在比赛，存在小概率把计时中的临时数据搅乱。现在临场最常用的几类操作（并组、微调、晋级、纪录）已经全部改成只发"这一条改动"的增量补丁，不再整包搬运，比赛中池边和编排席可以真正同时干活。

9.2 被拒时怎么办

被拒绝时编排端会明确告诉你原因（比如"该组正在比赛中，无法调整"），并自动把本机数据从主服务器重新取一次——你刚才在界面上的改动会被这次刷新覆盖掉。所以看到拒绝提示就要重做一遍，不要以为已经存上了。

  • 赛程导航树的组次状态标注改成读服务器下发的权威状态码（见 8.2 的数字对照表），不再凭"看起来做完了"猜，真正已确认的组才标 [已确认]，半截的组不会被误标
  • 盲表成绩按钮按下去之后，页面会明确提示"已用上这道的盲表时间"或失败原因，不再是按了看不出有没有生效

  • Ctrl+Shift+B 查询硬件按键备份：按一次只弹一个结果窗口，修复了此前关闭窗口后又跳出一个"无事件"的误报弹窗
  • 中间泳道实时状态区姓名/代表队的间距和字号调整为与 EXE 端一致，不再紧贴着圈数调整按钮

⚠ 本页没有「硬件连接」入口——网页端不直接接串口/网口，硬件连接只能在接了硬件的那台机器（EXE 或主服务器单机摆法）上做。

0x43 Set_MatchEvent（比赛准备）

  • D3 总圈数 / D4 右触板次数 / D5 左触板次数

  • D7 道次位图 5–9
  • D8 接力标志（1=接力 / 0=个人）

  • D3 泳道号 0–9（必须单道，不支持 0xFF）

0x47全部或单道整体启用 / 禁用 TP/SB/MB（不动道次按钮显示）
0x60仅单道同时切换 TP/SB/MB 启用 + 道次按钮显示状态
0x4C全部或单道设备状态机覆盖（接受所有信号 vs 按状态过滤）

  • D3 泳道号 0–9

A.4 帧间延迟

TimingBridge.DelayBetweenFrames(int ms = 50) 用于连续下发时的等待。硬件状态机串行处理，相邻帧间隔不足会丢帧：

场景延迟
0x43 之后 → 0x21 Ready20 ms
0x40 之后 → 0x42 子码序列（共 ~9 帧）50 ms × N
每道设备状态帧（最多 10 道）30 ms × N
0x20 复位后 → 任何后续帧50 ms

按下"M.发令"的总下发时延约 ~800 ms，业务可接受。

A.5 远程 EXE 转发（_REPORT 子命令族）

RemoteTimingControl.exe 直连硬件时，把硬件→PC 的扩展命令拆为 WebSocket TIMING_CMD 子命令转发给主服务器：

硬件帧WebSocket TIMING_CMDdata 字段
0x4B BatteryVoltageBATTERY_REPORT{ voltage }
0x64 TimingsBundleTIMINGS_BUNDLE_REPORT{ laneCloseTime, ... } 共 5 项
0x62 LaneOrderLANE_ORDER_REPORT`{ order: "forward""reverse" }`
0x63 FinishPositionFINISH_POS_REPORT`{ pos: "left""right" }`
0x3A PoolSingleOrDoublePOOL_SIDE_REPORT{ single: bool }
0x47 LaneOpenCloseLANE_OPEN_CLOSE_REPORT`{ lane: -10..9, open: bool }`

主服务器侧 HandleHardwareReportForwarded 还原为 TimingData 后调 ProcessTimingDataFromHardware 复用原处理路径。

仅适用于"EXE 直连硬件"模式；主服务器直连硬件时走 OnTimingData 原路径。
