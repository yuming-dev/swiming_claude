1. 系统概述

1.1 设计目标

本系统是一套完整的游泳比赛管理与计时解决方案，覆盖赛事全生命周期：

  • 赛前：赛事创建 / 运动员报名 / 自动或手动分组 / 秩序册编辑 / 纪录数据导入
  • 赛中：硬件计时实时联动 / 三端控制台同步 / 设备状态管理 / 大屏展示 / 媒体播放
  • 赛后：成绩确认与排名 / 多轮晋级 / 成绩册编辑 / 多格式文档输出（PDF / DOC / HTML）

系统遵循 World Aquatics（FINA）SW 3 竞赛规则 自动分组（循环 / 直接排位 + 矛头泳道分配）。

1.2 设计原则：服务器是单一数据源

所有大屏、排名屏、文档（编辑 / 输出 / 打印）显示的数据都来自比赛控制端（主服务器）。前端浏览器 / 打印模板直接渲染服务器广播的字段（sw.rank、sw.reactionTime、sw.legReactionTimes、sw.recordNote 等），不再做二次重排或重算。

任何"大屏显示某字段不对"、"打印某列不对"的问题，都先回到主服务器的记录 / 计算路径去修，让广播本身的数据正确，再让前端原样渲染。前端纯展示层格式化（小数位、HTML 转义、奖牌色映射）仍可在前端做。

3.1 三个计时控制台等价

主服务器 / RemoteTimingControl.exe / race_control.html 功能完全等价——任何一端按下准备就绪 / M.发令 / 确认本组成绩 / 计时复位，都通过 WebSocket 广播到其它两端 + 硬件，状态保持一致。

3.2 数据流单向：服务器 → 客户端

  • 运动员姓名 / 代表队 / 反应时 / 分段 / 名次 / 纪录 全部由服务器在广播载荷中直接给出。
  • 客户端不再二次重排名次、不再前端字符串拼接推算反应时。
  • 配置 / 控制类命令则客户端 → 服务器，再由服务器统一下发硬件 + 回广播。

3.3 编排端同步通道

ScheduleEditor.exe 通过 EditorSyncClient（WebSocket，复用 3002 端口）连主服务器：

消息 方向 用途
EDITOR_IDENTITY 编排端 → 服务器 连接后身份握手，请求当前 Package
EDITOR_PACKAGE 服务器 → 编排端 推送当前 CompetitionPackage 整包
EDITOR_PUSH_PACKAGE 编排端 → 服务器 编排端自动保存后推回，服务器再 broadcast 给其它编排端

_applyingRemoteSync 标志防止应用远端 Package 时回环。所有同步走 AutoSaveData 钩子，确保任何字段变化都能 30 秒内传到所有编排端。

4. 硬件通讯协议（命令字节表）

4.1 帧格式

F1 53 [CMD] [D3] [D4] [D5] [D6] [D7] [D8] [D9] [D10] F4
 │  │   │    └───────────── 8 字节数据 ─────────────┘    │

4.3 关键命令详解

0x43 Set_MatchEvent（比赛准备）

  • D3 总圈数 / D4 右触板次数 / D5 左触板次数
  • D6 道次位图 0–4（bit=1 即占用 / 开启）
  • D7 道次位图 5–9
  • D8 接力标志（1=接力 / 0=个人）
  • lane 索引按"屏幕位置"编码：逆序模式下 hwIndex = 9 − lane
  • 在"准备就绪"按下时发送，紧接 30–50 ms 延迟后再发 0x21 Ready

0x60 Set_LaneEnableDisable

  • D3 泳道号 0–9（必须单道，不支持 0xFF）
  • D4 1=启用 / 0=屏蔽（同时切换硬件道次按钮显示）

与 0x47 / 0x4C 三命令的语义区分：

命令 作用范围 效果
0x47 全部或单道 整体启用 / 禁用 TP/SB/MB（不动道次按钮显示）
0x60 仅单道 同时切换 TP/SB/MB 启用 + 道次按钮显示状态
0x4C 全部或单道 设备状态机覆盖（接受所有信号 vs 按状态过滤）

0x61 Set_LapRemaining

  • D3 泳道号 0–9
  • D4 端：0=左 / 1=右
  • D5 剩余圈数 0–255

PC 端"剩余圈数 ▲▼" spinner 调整后立即下发，硬件 laps[D3][D4] = D5 并重画对应道的圈数显示。

0x62 / 0x63 双向同步

  • 0x62 Set_LaneOrder：D3=0 正序 / 1 逆序
  • 0x63 Set_FinishPosition：D3=0 终点左端 / 1 终点右端

PC 改设置时下发硬件；硬件 net_test 子界面用户改后回主控时上报，PC 自动更新 _laneCloseSettings + ApplyTouchpadInstallModeToLanes() 刷新各道 NotInstalled + Broadcast() 推全客户端。双向命令均禁止回发以防回环。

0x64 Set_TimingsBundle（硬件 → PC）

硬件 net_test 子界面"参数设置"输入完 5 项时间编辑框后退出，把当前值一帧打包上报：

字段 含义 单位
D3 泳道封闭时间 LaneCloseTime 秒
D4 触板延迟关闭 ResultConfirmCloseDelay 秒
D5 出发台延迟关闭 StartBlockCloseDelay 秒
D6 盲表代替成绩延迟 BlindReplaceDelay 秒（整数）
D7 成绩显示时间 SplitDisplayTime 秒
⚠ BlindReplaceDelay 单位 v2026.05.18 起统一为"整数秒"；旧命令 0x41 D5 / 0x42 子码 0x09 是 0.1 秒精度，PC 端 SendXxx 时会乘 10 转换。硬件内部 MBdelay_Time = d5 * 10。

0x65 Set_RefreshDisplay

PC 参数对话框 OK 后下发，硬件主控按新参数主动重画一屏，但不丢失比赛状态（缺道 / 剩余圈数 / TP/SB/MB Open_State 全部保留再恢复）。D3–D10 全 0。

0x4B BatteryVoltage（硬件 → PC）

D3:D4 大端 mV，主控 = (D3<<8 | D4) / 1000.0 V。

区间 颜色
≥ 7.4 V 绿
6.8 ~ 7.4 V 黄
< 6.8 V 红

接收后实时刷新主服务器"系统硬件"栏 + 远程台顶栏。30 秒无更新自动置 "—"。

0x39 Set_DateTime（周期校时）

连接硬件后立即下发一次；之后 DispatcherTimer _clockSyncTimer 每 30 分钟刷一次。字段 D3 YearLo / D4 YearHi / D5 Month / D6 Day / D7 Hour / D8 Min / D9 Sec。

4.4 帧间延迟

TimingBridge.DelayBetweenFrames(int ms = 50) 用于连续下发时的等待。硬件状态机串行处理，相邻帧间隔不足会丢帧：

场景 延迟
0x43 之后 → 0x21 Ready 20 ms
0x40 之后 → 0x42 子码序列（共 ~9 帧） 50 ms × N
每道设备状态帧（最多 10 道） 30 ms × N
0x20 复位后 → 任何后续帧 50 ms

按下"M.发令"的总下发时延约 ~800 ms，业务可接受。

4.5 远程 EXE 转发（_REPORT 子命令族）

RemoteTimingControl.exe 直连硬件时，把硬件→PC 的扩展命令拆为 WebSocket TIMING_CMD 子命令转发给主服务器：

硬件帧 WebSocket TIMING_CMD data 字段
0x4B BatteryVoltage BATTERY_REPORT { voltage }
0x64 TimingsBundle TIMINGS_BUNDLE_REPORT { laneCloseTime, ... } 共 5 项
0x62 LaneOrder LANE_ORDER_REPORT `{ order: "forward" "reverse" }`
0x63 FinishPosition FINISH_POS_REPORT `{ pos: "left" "right" }`
0x3A PoolSingleOrDouble POOL_SIDE_REPORT { single: bool }

主服务器侧 HandleHardwareReportForwarded 还原为 TimingData 后调 ProcessTimingDataFromHardware 复用原处理路径。

仅适用于"EXE 直连硬件"模式；主服务器直连硬件时走 OnTimingData 原路径。

10 道 4, 5, 3, 6, 2, 7, 1, 8, 0, 9

10.13 接力 4 棒反应时

每棒交接时，服务器按棒次索引覆盖写入 LaneResult.LegReactionTimes[legIdx]：

  • 第 1 棒反应时 = 出发台时间（相对发令信号）
  • 第 N+1 棒反应时 = 第 N+1 棒出发台时间 − 第 N 棒触板累计时间（N=1, 2, 3）
  • 由 ComputeRelayLegIndex(currentLap) 推算棒次索引，按索引"覆盖写入"
  • 同步广播 sw.reactionSeq（LaneDeviceState.ReactionTime setter 每次自增），客户端用它检测"新一棒反应时"，重启大屏备注栏 5 秒倒计时窗口
  • 个人项目仍是 StartingBlockTime 单值

  • 泳道字段（道次 / 姓名 / 队伍 / 成绩 / 名次 / 备注）：250 ms 廉价刷新 + 收到广播时刷新；字段对比，仅写差异
  • 滚动时间在确认成绩后清空：_updateRunningTimeOnly 检测 data.resultConfirmed === true 时直接清空文本

14.5 空泳道不显示

_activeSwimmersForDisplay 滤除 status==='EMPTY' 或无姓名+无号码的占位行；isOccupiedLane 过滤 0 道无人。

14.6 隐私保护

服务器广播载荷取消 notes 字段，避免运动员个人备注（姓名 / 单位 / 教练等）泄露到大屏；报名端通过独立的 REGISTER_QUERY_RESULT 通道获取 notes。

26. 常见问题

26.1 主服务器闪退或无法启动

  • 查看是否被防病毒软件拦截
  • 检查 .NET Framework 4.5+ 是否安装
  • 端口 3002 是否被其它进程占用

26.2 客户端连不上主服务器

  • 检查 IP 是否正确（用 ipconfig 确认主机 IP）
  • 防火墙是否放行 SwimmingScoreboard.exe
  • 主服务器右下角"连接状态"是否显示已启动 WebSocket
  • 浏览器端启动遮罩里的 IP 输入框可重输；按 3 次失败后会弹 confirm 询问是否换地址

26.3 顶部"硬件计时器"一直红色

  • 主服务器：检查"系统工作状态 → 硬件计时器连接"是否选好协议（TCP/UDP/串口）并按了连接
  • EXE 远程台：顶栏自身的硬件指示灯是 EXE 直连硬件的状态；如果只走主服务器代理，这里也会亮
  • 已连接但红？看主控日志窗口是否有"超时"提示——硬件可能掉线，可点"网络连接"重连

26.4 标 DSQ 后该道触板/盲表不工作

  • 已修复：DSQ 道继续接收原始数据（触板 / 盲表 / 分段 / 反应时全部继续记录）；仅大屏排名 / 最终成绩排除该道。如果还是不工作，确认 EXE 是 v2026.05.20+ 版本

26.5 道次顺序改成"逆序"后硬件道次发错

  • 已修复（v2026.05.18 6081107）：所有 PC→硬件帧的 lane 字段都按"屏幕位置"编码，逆序时 hwIndex = 9 − lane
  • 若仍异常，确认主服务器和 EXE 都升到 v2026.05.20+，并重启硬件让 0x65 RefreshDisplay 把状态对齐

26.6 一组多人破纪录但大屏只显示第 1 名的标识

  • 这是 FINA 标准行为（EnforceOnlyLeaderRecordNote）。第 1 名（含 5 ms 内并列）保留 RecordNote，其余清空

26.7 已确认成绩消失

  • 检查"赛程导航"是否仍显示 [已完赛]
  • 在"成绩与排名" Tab 检查组次下拉是否包含该组
  • 查看主控日志窗口是否有"赛程导航刷新失败 / 成绩与排名刷新失败"红色错误

26.8 接力打印反应时少于 4 棒

  • 服务器按棒次索引覆盖写入 LegReactionTimes，槽位数固定 = 项目名 N×D 的 N
  • 未触发硬件事件的棒次显示 —

26.9 ScheduleEditor 启动很慢 / 一直显示"未连接"

  • 编排端不开 3002 端口（不是 WebSocket 服务器），需要连主服务器
  • 点顶栏 "EditorSync" 工具条内的"连接"按钮，输入主服务器 IP
  • 主服务器必须先启动，编排端才能拉到 CompetitionPackage

26.10 编排端改成绩，主服务器看不到

  • 编排端 AutoSaveData 时通过 EDITOR_PUSH_PACKAGE 整包推主服务器，主服务器再 broadcast 给其它编排端
  • 若网络抖动可能丢包；重启编排端会重新拉一次完整 Package

26.11 设备测试期间硬件没有响应

  • 设备测试发送 0x1D 给硬件；如果硬件固件不识别 0x1D（旧固件），仅 PC 端进入测试模式，硬件不做任何配合，事件链路可能失效
  • 升级硬件固件到 v2026.05.20+ 解决

26.12 电池电压一直显示 "—"

  • 硬件需主动上报 0x4B BatteryVoltage（连接后会立即报一次，电压变化时也会报）
  • 30 秒无新报会清空显示
  • 旧固件不支持 0x4B 时永远 "—"，升级固件解决

26.13 大屏卡顿

  • 已优化为分区刷新（100 ms 滚动时间 + 250 ms 廉价字段刷新 + DOM 缓存）
  • 老版本浏览器（IE / 旧 Edge）渲染慢，建议 Chrome / 新 Edge

26.14 自动分组结果不符合 FINA 规则

  • 请确认"项目类型"识别正确（短距 50/100/200 / 中长距离 400+ / 接力）
  • 重新点 预赛自动分组

26.15 接力队员重复登记

  • 已修复：相同 (队名 + 性别 + 项目) 的接力队会被识别为更新，不会增加重复行

26.16 计时复位后大屏没切到欢迎画面

  • 仅在"本赛次最后一组已确认 + 计时复位"才会切欢迎画面
  • 中间组的清零会自动切到下一组（仍显示比赛视图）
